<h2 class="post-h2">The Problem: Arrays Aren't Always the Answer</h2>

<p class="post-p">
JavaScript developers love chaining array methods:
</p>

<pre class="code-block"><code class="language-javascript">const result = data
<p class="post-p">
.filter(item =&amp;gt; item.active)
.map(item =&amp;gt; item.name)
.slice(0, 10);
</code></pre>
</p>

<p class="post-p">
This pattern is clean, readable, and declarative. But it has a hidden cost: <strong>each step creates a new intermediate array</strong>. With 10,000 items, that's three full passes and two temporary arrays. With a generator yielding infinite values, it flat-out doesn't work.
</p>

<p class="post-p">
Enter <strong>Iterator Helpers</strong> — the same <code class="inline-code">.map()</code>, <code class="inline-code">.filter()</code>, <code class="inline-code">.take()</code>, <code class="inline-code">.drop()</code>, <code class="inline-code">.flatMap()</code>, <code class="inline-code">.reduce()</code>, <code class="inline-code">.find()</code>, <code class="inline-code">.some()</code>, <code class="inline-code">.every()</code>, and <code class="inline-code">.forEach()</code> methods, but on <strong>any iterable</strong> (generators, Sets, Maps, strings, NodeLists, custom iterators) — lazily evaluated, zero intermediate arrays.
</p>

<pre class="code-block"><code class="language-javascript">// Instead of:
<p class="post-p">
[...set].filter(x =&amp;gt; x &amp;gt; 5).map(x =&amp;gt; x * 2);
</p>

<p class="post-p">
// You write:
set.values().filter(x =&amp;gt; x &amp;gt; 5).map(x =&amp;gt; x * 2).toArray();
</code></pre>
</p>

<p class="post-p">
No intermediate arrays. Just a pipeline of lazy transformations.
</p>

<h2 class="post-h2">The Iterator Namespace</h2>

<p class="post-p">
Every iterable's <code class="inline-code">.values()</code> method (or the iterable itself via <code class="inline-code">Iterator.from()</code>) now exposes a full chainable API:
</p>

<pre class="code-block"><code class="language-javascript">// On any iterable
<p class="post-p">
const it = Iterator.from(someIterable);
</p>

<p class="post-p">
// Or directly on built-in iterators
const it = map.values(); // MapIterator
const it = set.values(); // SetIterator
const it = generator();  // Generator object
</code></pre>
</p>

<p class="post-p">
All of these now have <code class="inline-code">.map()</code>, <code class="inline-code">.filter()</code>, <code class="inline-code">.take()</code>, and the rest.
</p>

<h2 class="post-h2">Every Iterator Helper Method</h2>

<h3 class="post-h3"><code class="inline-code">.map(fn)</code> — Transform each value</h3>

<pre class="code-block"><code class="language-javascript">function* fibonacci() {
<p class="post-p">
let a = 0, b = 1;
while (true) { yield a; [a, b] = [b, a + b]; }
}
</p>

<p class="post-p">
// Square the first 10 fibonacci numbers — all lazy, no infinite loop
const squares = fibonacci()
.take(10)
.map(n =&amp;gt; n * n)
.toArray();
// [0, 1, 1, 4, 9, 25, 64, 169, 441, 1156]
</code></pre>
</p>

<p class="post-p">
Notice: <code class="inline-code">.take(10)</code> stops the infinite generator, and <code class="inline-code">.map()</code> only transforms the 10 values that make it through. No wasted work.
</p>

<h3 class="post-h3"><code class="inline-code">.filter(fn)</code> — Keep only matching values</h3>

<pre class="code-block"><code class="language-javascript">// Get active admins from a Map of user records
<p class="post-p">
const users = new Map([
['alice', { role: 'admin', active: true }],
['bob',   { role: 'user',  active: true }],
['carol', { role: 'admin', active: false }],
['dave',  { role: 'admin', active: true }],
]);
</p>

<p class="post-p">
const activeAdmins = users.values()
.filter(u =&amp;gt; u.role === 'admin')
.filter(u =&amp;gt; u.active)
.toArray();
// [{ role: 'admin', active: true }, { role: 'admin', active: true }]
</code></pre>
</p>

<h3 class="post-h3"><code class="inline-code">.take(n)</code> — Take the first N values</h3>

<pre class="code-block"><code class="language-javascript">// Read first 5 lines of a large file (via streaming generator)
<p class="post-p">
function* readLines(stream) {
// ... streaming file read
}
</p>

<p class="post-p">
const preview = readLines(hugeFile)
.take(5)
.toArray();
</code></pre>
</p>

<p class="post-p">
This is the killer feature for infinite generators and large datasets. Stop processing after N items without reading everything.
</p>

<h3 class="post-h3"><code class="inline-code">.drop(n)</code> — Skip the first N values</h3>

<pre class="code-block"><code class="language-javascript">// Skip header row, then process
<p class="post-p">
const csvLines = rawLines.drop(1).map(parseRow).toArray();
</code></pre>
</p>

<h3 class="post-h3"><code class="inline-code">.flatMap(fn)</code> — Map and flatten</h3>

<pre class="code-block"><code class="language-javascript">// Expand each user's roles
<p class="post-p">
const allRoles = users.values()
.flatMap(u =&amp;gt; u.roles)  // Each user.roles is an array
.toArray();
</code></pre>
</p>

<h3 class="post-h3"><code class="inline-code">.reduce(fn, initial)</code> — Fold values into a single result</h3>

<pre class="code-block"><code class="language-javascript">const total = orders.values()
<p class="post-p">
.map(o =&amp;gt; o.total)
.reduce((sum, val) =&amp;gt; sum + val, 0);
</code></pre>
</p>

<h3 class="post-h3"><code class="inline-code">.find(fn)</code> — Return first match (or undefined)</h3>

<pre class="code-block"><code class="language-javascript">const firstAdmin = users.values().find(u =&amp;gt; u.role === 'admin');
<p class="post-p">
</code></pre>
</p>

<h3 class="post-h3"><code class="inline-code">.some(fn)</code> — Does any value satisfy the predicate?</h3>

<pre class="code-block"><code class="language-javascript">const hasInactive = users.values().some(u =&amp;gt; !u.active);
<p class="post-p">
</code></pre>
</p>

<h3 class="post-h3"><code class="inline-code">.every(fn)</code> — Do all values satisfy the predicate?</h3>

<pre class="code-block"><code class="language-javascript">const allActive = users.values().every(u =&amp;gt; u.active);
<p class="post-p">
</code></pre>
</p>

<h3 class="post-h3"><code class="inline-code">.forEach(fn)</code> — Execute for each value (terminal)</h3>

<pre class="code-block"><code class="language-javascript">// Log each active user — processes lazily, one at a time
<p class="post-p">
users.values()
.filter(u =&amp;gt; u.active)
.forEach(u =&amp;gt; console.log(u.name));
</code></pre>
</p>

<h3 class="post-h3"><code class="inline-code">.toArray()</code> — Collect into an array (terminal)</h3>

<p class="post-p">
The most common terminal operation. Collects all remaining values into a regular array.
</p>

<pre class="code-block"><code class="language-javascript">const result = pipeline.filter(...).map(...).take(10).toArray();
<p class="post-p">
</code></pre>
</p>

<h2 class="post-h2">Lazy Evaluation: The Secret Superpower</h2>

<p class="post-p">
The key difference from array methods: <strong>nothing executes until a terminal method is called</strong>.
</p>

<pre class="code-block"><code class="language-javascript">function* count() {
<p class="post-p">
let i = 0;
while (true) {
console.log('yielding', i);
yield i++;
}
}
</p>

<p class="post-p">
// This creates the pipeline — but NOTHING logs yet
const pipeline = count()
.filter(n =&amp;gt; n % 2 === 0)
.map(n =&amp;gt; n * 10)
.take(3);
</p>

<p class="post-p">
// Still nothing logged. The pipeline is just a description.
</p>

<p class="post-p">
// NOW it executes — and logs exactly 5 yields to produce 3 even numbers
const result = pipeline.toArray();
// yielding 0   ← 0 even, mapped
// yielding 1   ← filtered out
// yielding 2   ← 2 even, mapped
// yielding 3   ← filtered out
// yielding 4   ← 4 even, mapped — we have 3, stop!
// result: [0, 20, 40]
</code></pre>
</p>

<p class="post-p">
Only 5 yields for 3 results. With arrays, every value would be processed through every step.
</p>

<h2 class="post-h2">Production Pattern: Paginated API Client</h2>

<pre class="code-block"><code class="language-typescript">async function* paginatedFetch&amp;lt;T&amp;gt;(url: string): AsyncGenerator&amp;lt;T&amp;gt; {
<p class="post-p">
let page = 1;
let hasMore = true;
</p>

<p class="post-p">
while (hasMore) {
const res = await fetch(<code class="inline-code">${url}?page=${page}&amp;amp;limit=100</code>);
const data = await res.json();
for (const item of data.items) yield item;
hasMore = data.hasMore;
page++;
}
}
</p>

<p class="post-p">
// Consume with iterator helpers
const filtered = Iterator.from(
await paginatedFetch&amp;lt;User&amp;gt;('/api/users')
).filter(u =&amp;gt; u.active)
.take(500)
.map(u =&amp;gt; ({ id: u.id, name: u.name }))
.toArray();
</code></pre>
</p>

<p class="post-p">
Memory-efficient even with millions of records — only 500 are held in memory at the end, and the fetch stops once we have enough.
</p>

<h2 class="post-h2">Production Pattern: DOM Traversal</h2>

<pre class="code-block"><code class="language-typescript">function* walkDOM(root: Element): Generator&amp;lt;Element&amp;gt; {
<p class="post-p">
yield root;
for (const child of root.children) {
yield* walkDOM(child);
}
}
</p>

<p class="post-p">
// Find all buttons with a specific aria-label — lazily, stops at first match
const button = walkDOM(document.body)
.filter(el =&amp;gt; el.tagName === 'BUTTON')
.find(el =&amp;gt; el.getAttribute('aria-label') === 'Submit');
</p>

<p class="post-p">
// Find all elements matching a selector, take first 5
const firstFiveLinks = walkDOM(document.body)
.filter(el =&amp;gt; el.matches('a[href^="https"]'))
.take(5)
.toArray();
</code></pre>
</p>

<p class="post-p">
No more <code class="inline-code">document.querySelectorAll()</code> collecting every match when you only need a few.
</p>

<h2 class="post-h2">Production Pattern: Data Pipeline Composition</h2>

<pre class="code-block"><code class="language-typescript">// Compose reusable pipeline stages
<p class="post-p">
const byStatus = (status: string) =&amp;gt;
function* &amp;lt;T extends { status: string }&amp;gt;(items: Iterable&amp;lt;T&amp;gt;) {
yield* Iterator.from(items).filter(item =&amp;gt; item.status === status);
};
</p>

<p class="post-p">
const topN = &amp;lt;T&amp;gt;(n: number) =&amp;gt;
function* (items: Iterable&amp;lt;T&amp;gt;) {
yield* Iterator.from(items).take(n);
};
</p>

<p class="post-p">
const pluck = &amp;lt;T, K extends keyof T&amp;gt;(key: K) =&amp;gt;
function* (items: Iterable&amp;lt;T&amp;gt;) {
yield* Iterator.from(items).map(item =&amp;gt; item[key]);
};
</p>

<p class="post-p">
// Compose them
const pipeline = pipe(
byStatus('active'),
topN(10),
pluck('name'),
);
</p>

<p class="post-p">
const names = pipeline(items).toArray();
</code></pre>
</p>

<h2 class="post-h2">Async Iterator Helpers</h2>

<p class="post-p">
Async iterators (<code class="inline-code">for await...of</code>) get their own parallel set of helpers via <code class="inline-code">Iterator.from()</code>:
</p>

<pre class="code-block"><code class="language-typescript">async function* eventStream(url: string) {
<p class="post-p">
const response = await fetch(url);
const reader = response.body!.getReader();
// ... SSE parsing
}
</p>

<p class="post-p">
const recentEvents = Iterator.from(eventStream('/api/events'))
.filter(e =&amp;gt; e.severity === 'critical')
.take(20)
.map(e =&amp;gt; e.message);
</code></pre>
</p>

<p class="post-p">
Async methods return async iterators, and terminal methods return promises.
</p>

<h2 class="post-h2">Comparison: Array vs Iterator Approaches</h2>

<p class="post-p">
| Aspect | Array Methods | Iterator Helpers |
|--------|--------------|------------------|
| Intermediate allocations | One new array per method | Zero |
| Works with infinite iterables | No | Yes |
| Works with generators | Only after <code class="inline-code">.toArray()</code> | Natively |
| Memory for 100K items, 3-step pipeline | ~300K items allocated | ~100K (only terminal) |
| Early termination | Process everything | Stop when done |
| Debuggability | Logs at each step | Logs at yield time |
</p>

<h2 class="post-h2">The One Gotcha: Iterator Exhaustion</h2>

<p class="post-p">
Iterators are stateful. Once consumed, they're empty:
</p>

<pre class="code-block"><code class="language-javascript">const it = [1, 2, 3].values().map(n =&amp;gt; n * 2);

<p class="post-p">
it.toArray(); // [2, 4, 6]
it.toArray(); // [] — exhausted!
</p>

<p class="post-p">
// Fix: create fresh iterators or tee them
</code></pre>
</p>

<p class="post-p">
If you need multiple passes over the same data, either <code class="inline-code">.toArray()</code> early or create fresh iterators.
</p>

<h2 class="post-h2">Takeaway</h2>

<p class="post-p">
Iterator Helpers close the gap between the elegant array method chain and the efficiency of lazy iterators. The key insights:
</p>

<ul class="post-ul"><li class="post-li"><strong>Everything is lazy</strong> — no intermediate arrays, no wasted work</li>
<li class="post-li"><strong>Works on anything iterable</strong> — generators, Maps, Sets, NodeLists, strings, custom iterators</li>
<li class="post-li"><strong><code class="inline-code">.take()</code> and <code class="inline-code">.drop()</code> are game-changers</strong> for pagination and infinite sequences</li>
<li class="post-li"><strong>Composable pipelines</strong> — build reusable transformation stages</li>
<li class="post-li"><strong>Shipping now</strong> — no transpilation needed in modern browsers</li>
</ul>
<p class="post-p">
The next time you write <code class="inline-code">.filter().map().slice()</code> on an array, ask yourself: could this be an iterator pipeline instead?
</p>
