CSS Stepped Value Functions — `round()`, `mod()`, and `rem()` — went Baseline in 2024. They're the final piece of the CSS math puzzle, joining trig functions, `pow()`/`sqrt()`, and the comparison functions (`min()`, `max()`, `clamp()`). If you're still doing stepped arithmetic in JavaScript and passing it to CSS via inline styles or custom properties computed at runtime, it's time to stop.

## What We Got

| Function | Signature | What It Does |
|----------|-----------|-------------|
| `round(strategy, A, B)` | `round(<strategy>, <number>, <number>)` | Rounds A to the nearest integer multiple of B |
| `mod(A, B)` | `mod(<number>, <number>)` | Returns the remainder of A ÷ B, with the **sign of B** |
| `rem(A, B)` | `rem(<number>, <number>)` | Returns the remainder of A ÷ B, with the **sign of A** |

All three accept `<number>` or `<dimension>` arguments (as long as units match) and return the same type. They work in `calc()`, custom properties, and anywhere a numeric value is accepted.

## `round()`: Snap to Multiples

`round()` rounds a value to the nearest multiple of a step size. Think of it as a CSS-native grid snap.

### Syntax

```css
round(<strategy>, A, B)
```

- **A**: The value to round
- **B**: The step size (rounding interval)
- **strategy**: One of `nearest`, `up`, `down`, `to-zero`

### Strategies

| Strategy | Behavior | Example: `round(strategy, 7, 4)` |
|----------|----------|----------------------------------|
| `nearest` | Round to nearest multiple | `round(nearest, 7, 4)` → 8 |
| `up` | Always round up (ceiling) | `round(up, 7, 4)` → 8 |
| `down` | Always round down (floor) | `round(down, 7, 4)` → 4 |
| `to-zero` | Round toward zero | `round(to-zero, 7, 4)` → 4 |

```css
/* Round font size to the nearest 4px grid step */
.element {
  font-size: round(nearest, 1.25em, 4px);
}

/* Always round element heights up to multiples of 8px */
.element {
  min-height: round(up, calc(100% + 16px), 8px);
}
```

### Real Pattern: Pixel-Grid Alignment

Ever had elements that don't quite align because of fractional pixel values? `round()` fixes it:

```css
.grid-item {
  /* Force every item's width to a multiple of 8px */
  width: round(nearest, calc(100% / var(--columns)), 8px);
}
```

This is especially powerful in layout engines where sub-pixel rendering creates 0.5px gaps between elements. By snapping every computed dimension to a grid step, you guarantee perfect alignment.

### Real Pattern: Fluid Typography Grid

```css
/* Type scale that snaps to 2px increments */
:root {
  --base: 16px;
  --ratio: 1.25;
  --step: 2px;
  
  --h1: round(nearest, calc(var(--base) * var(--ratio) * var(--ratio) * var(--ratio)), var(--step));
  --h2: round(nearest, calc(var(--base) * var(--ratio) * var(--ratio)), var(--step));
  --h3: round(nearest, calc(var(--base) * var(--ratio)), var(--step));
  --body: round(nearest, var(--base), var(--step));
}
```

Every type scale value is a clean multiple of 2px. No more `16.25px` font sizes that render blurry on some screens.

## `mod()`: Cyclic / Wrapping Values

`mod(A, B)` returns the remainder after dividing A by B, matching the **sign of B**. This makes it perfect for cyclic values — wrapping indices, rotating through colors, infinite carousels.

```css
mod(A, B) = A - B * floor(A / B)
```

The result always has the same sign as B, which means it wraps cleanly even with negative inputs:

```css
mod(10, 3)  → 1   /* 10 = 3×3 + 1 */
mod(-10, 3) → 2   /* -10 = 3×(-4) + 2 */
mod(10, -3) → -2  /* 10 = (-3)×(-4) + (-2) */
mod(-10, -3) → -1 /* -10 = (-3)×3 + (-1) */
```

### Real Pattern: Rotating Color Palette

```css
.cards:nth-child(n) {
  /* Rotate through 5 theme colors, wrapping around */
  --hue: calc(mod(var(--index) - 1, 5) * 72);
  background: hsl(var(--hue), 70%, 60%);
}
```

As the card index grows (3, 7, 12, 50...), `mod()` keeps the hue cycling through 0°, 72°, 144°, 216°, 288°.

### Real Pattern: Zebra-Striped Grid Rows

```css
.table-row:nth-child(n) {
  /* 3-row repeating pattern: white, light gray, medium gray */
  --stripe: mod(var(--row-index), 3);
  background: hsl(0, 0%, calc(100% - var(--stripe) * 3%));
}
```

Without `mod()`, you'd write three separate `:nth-child(3n+1)`, `:nth-child(3n+2)`, `:nth-child(3n+3)` rules. With `mod()`, it's a single property.

### Real Pattern: Infinite Wrap-Around Positioning

```css
.carousel-item {
  /* Position items in a ring — wraps endlessly */
  --angle: calc(mod(var(--index), var(--total)) * (360deg / var(--total)));
  transform: rotate(var(--angle)) translateX(200px);
}
```

As `--index` increases beyond `--total`, the angle wraps back to 0° seamlessly. This is the foundation of pure-CSS carousels, orbital menus, and circular layouts.

## `rem()`: Classic Remainder

`rem(A, B)` returns the remainder using the **sign of A**:

```css
rem(A, B) = A - B * trunc(A / B)
```

```css
rem(10, 3)  → 1   /* 10 = 3×3 + 1 */
rem(-10, 3) → -1  /* -10 = 3×(-3) + (-1) */
rem(10, -3) → 1   /* 10 = (-3)×(-3) + 1 */
rem(-10, -3) → -1 /* -10 = (-3)×3 + (-1) */
```

### `mod()` vs `rem()`: When to Use Each

| Scenario | Use | Why |
|----------|-----|-----|
| Wrapping cyclic values (indices, angles) | `mod()` | Always returns non-negative when B > 0 |
| JS-compatible math (matches `%` operator) | `rem()` | Same behavior as JavaScript `%` |
| Layout calculations where direction matters | `rem()` | Carries source sign for directional logic |
| Color wheel rotation, carousel positions | `mod()` | You want 0–360°, not negative angles |

```css
/* mod() — always gives a useful angle (0–360) */
transform: rotate(mod(var(--scroll), 360deg));

/* rem() — matches JS behavior, useful when porting logic */
--offset: rem(var(--total-scroll), var(--section-height));
```

The critical practical difference: for cyclic wrapping (the most common use case), always reach for `mod()`.

## The Full Stepped-Value Toolkit

Combined with trig and comparison functions, these create a declarative layout math engine in CSS:

```css
:root {
  /* Snap to grid */
  --snap: round(nearest, var(--value), 8px);
  
  /* Cyclic animation state */
  --cycle: mod(calc(var(--frame) + var(--offset)), var(--length));
  
  /* JS-compatible remainder */
  --remainder: rem(var(--total), var(--chunk));
  
  /* All together: animated grid-snapped cyclic pattern */
  --pos: round(nearest, 
    calc(
      sin(mod(var(--frame), 360) * 1deg) * 100px + 200px
    ), 
    8px
  );
}
```

## Performance Note

CSS math functions are evaluated at **computed-value time** by the browser's layout engine. They don't trigger JavaScript execution, they don't cause recalc loops, and they're hardware-accelerated the same way as static values. A `round(nearest, ...)` is as fast as a hardcoded pixel value — the browser computes it once during layout.

Compare this to computing stepped values in JavaScript and injecting them via inline styles: you pay the cost of JS execution, style invalidation, and potentially a forced synchronous layout. CSS stepped value functions eliminate that entire class of performance pitfalls.
