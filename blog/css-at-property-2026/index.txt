<h2 class="post-h2">What Is @property?</h2>

<p class="post-p">
The <code class="inline-code">@property</code> at-rule lets you define typed CSS custom properties directly in your stylesheet. Unlike regular custom properties (<code class="inline-code">--color: blue</code>), <code class="inline-code">@property</code> properties have a defined syntax type, inheritance behavior, and initial value.
</p>

<p class="post-p">
This typing is the key innovation — it tells the browser engine what kind of value to expect, which enables smooth interpolation in animations and transitions.
</p>

<h2 class="post-h2">Why Typed Properties Matter</h2>

<p class="post-p">
Without <code class="inline-code">@property</code>, custom properties are treated as strings. The browser can't interpolate between two arbitrary string values. With <code class="inline-code">@property</code>, the browser knows it's dealing with a <code class="inline-code">&lt;color&gt;</code>, <code class="inline-code">&lt;length&gt;</code>, or <code class="inline-code">&lt;angle&gt;</code> and can animate between them smoothly.
</p>

<pre class="code-block"><code class="language-css">@property --gradient-angle {
<p class="post-p">
syntax: '&amp;lt;angle&amp;gt;';
inherits: false;
initial-value: 0deg;
}
</p>

<p class="post-p">
.gradient-spin {
--gradient-angle: 0deg;
background: conic-gradient(
from var(--gradient-angle),
#06b6d4,
#8b5cf6,
#06b6d4
);
animation: spin 3s linear infinite;
}
</p>

<p class="post-p">
@keyframes spin {
to { --gradient-angle: 360deg; }
}
</code></pre>
</p>

<p class="post-p">
This was impossible before <code class="inline-code">@property</code> — you couldn't animate gradient angles with pure CSS because the browser couldn't interpolate a custom property between <code class="inline-code">0deg</code> and <code class="inline-code">360deg</code>.
</p>

<h2 class="post-h2">Key Syntax Types</h2>

<p class="post-p">
The <code class="inline-code">@property</code> rule supports all major CSS value types:
</p>

<p class="post-p">
| Syntax | Example | Animatable |
|--------|---------|------------|
| <code class="inline-code">&lt;color&gt;</code> | <code class="inline-code">#3b82f6</code> | ✓ Smooth color interpolation |
| <code class="inline-code">&lt;length&gt;</code> | <code class="inline-code">16px</code>, <code class="inline-code">2rem</code> | ✓ Length interpolation |
| <code class="inline-code">&lt;percentage&gt;</code> | <code class="inline-code">50%</code> | ✓ Percentage interpolation |
| <code class="inline-code">&lt;angle&gt;</code> | <code class="inline-code">45deg</code> | ✓ Angle interpolation |
| <code class="inline-code">&lt;number&gt;</code> | <code class="inline-code">0.5</code> | ✓ Number interpolation |
| <code class="inline-code">&lt;time&gt;</code> | <code class="inline-code">2s</code> | ✓ Time interpolation |
| <code class="inline-code">&lt;transform-function&gt;</code> | <code class="inline-code">rotate(0deg)</code> | ✓ Individual transforms |
</p>

<h2 class="post-h2">Real-World Patterns</h2>

<h3 class="post-h3">1. Animated Progress Bars</h3>

<pre class="code-block"><code class="language-css">@property --progress {
<p class="post-p">
syntax: '&amp;lt;percentage&amp;gt;';
inherits: false;
initial-value: 0%;
}
</p>

<p class="post-p">
.progress-bar {
--progress: 0%;
width: var(--progress);
background: linear-gradient(90deg, #06b6d4, #8b5cf6);
animation: fill 2s ease-in-out forwards;
}
</p>

<p class="post-p">
@keyframes fill {
to { --progress: 100%; }
}
</code></pre>
</p>

<h3 class="post-h3">2. Smooth Color Theme Transitions</h3>

<pre class="code-block"><code class="language-css">@property --theme-primary {
<p class="post-p">
syntax: '&amp;lt;color&amp;gt;';
inherits: true;
initial-value: #3b82f6;
}
</p>

<p class="post-p">
html {
--theme-primary: #3b82f6;
transition: --theme-primary 0.3s ease;
}
</p>

<p class="post-p">
html[data-theme="dark"] {
--theme-primary: #818cf8;
}
</code></pre>
</p>

<p class="post-p">
Now switching themes animates smoothly — button colors, link colors, and any element using <code class="inline-code">var(--theme-primary)</code> will transition gracefully.
</p>

<h3 class="post-h3">3. Gradient Sweep</h3>

<pre class="code-block"><code class="language-css">@property --sweep-angle {
<p class="post-p">
syntax: '&amp;lt;angle&amp;gt;';
inherits: false;
initial-value: 0deg;
}
</p>

<p class="post-p">
.sweep {
background: conic-gradient(
from var(--sweep-angle),
#06b6d4, #8b5cf6, #06b6d4
);
animation: sweep 4s linear infinite;
}
</code></pre>
</p>

</p>

<ul class="post-ul"><li class="post-li">Chrome 85+</li>

</ul>
<p class="post-p">
No polyfills needed. Ship it in production.
</p>

<h2 class="post-h2">The Future: @property Meets Style Queries</h2>

<p class="post-p">
The next frontier is combining <code class="inline-code">@property</code> with style queries. Style queries let you check the computed value of a custom property and conditionally apply styles:
</p>

<pre class="code-block"><code class="language-css">@container style(--theme: dark) {
<p class="post-p">
.card {
background: #1e293b;
}
}
</code></pre>
</p>

<p class="post-p">
This pattern eliminates the need for JavaScript-based theme switching entirely. Define your theme tokens as typed custom properties, and let style queries handle the conditional rendering.
</p>
