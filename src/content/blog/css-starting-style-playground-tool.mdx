## The Problem: You Can't Animate display

For decades, one CSS limitation has frustrated every frontend developer: you can't transition from `display: none`. Want a dialog to fade in when it opens? You need JavaScript. Want a tooltip to slide in smoothly? JavaScript. The browser simply has no "before" state to transition from when an element enters the DOM.

## The Solution: @starting-style

CSS `@starting-style` (Baseline 2026) gives you that missing starting point. It defines what an element looks like in its very first frame — before any transitions apply:

```css
.dialog {
  opacity: 1;
  transform: scale(1);
  transition: opacity 0.3s, transform 0.3s, display 0.3s allow-discrete;
}

@starting-style {
  .dialog {
    opacity: 0;
    transform: scale(0.95);
  }
}
```

When `.dialog` appears (via popover API, `dialog.showModal()`, or removing `display: none`), it starts invisible and slightly scaled down, then smoothly transitions to its final state. That's it — no JavaScript, no libraries, no `requestAnimationFrame()` hacks.

## Browser Support

`@starting-style` is now Baseline across Chrome 117+, Safari 17.5+, and Firefox 129+. For browsers that don't support it, the element still appears — just without the entry animation. It's a perfect progressive enhancement.

## Pair With transition-behavior

To get the full effect, you'll want `transition-behavior: allow-discrete` on the `display` property. This tells the browser to apply `display` changes at the animation boundary instead of skipping them entirely:

```css
transition: opacity 0.2s, transform 0.2s, display 0.2s allow-discrete;
```

For exit animations, reverse the pattern — transition to `opacity: 0` and then set `display: none` at the end of the transition.
