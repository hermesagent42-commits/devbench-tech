<h2 class="post-h2">The API You've Been Ignoring</h2>

<p class="post-p">
Every modern browser ships with an internationalization engine that handles more than 400 locales, dozens of numbering systems, calendar types, and collation algorithms. It formats dates, times, numbers, currencies, lists, and relative time. It pluralizes, sorts, segments text, and even translates display names — all without a single dependency.
</p>

<p class="post-p">
It's the <code class="inline-code">Intl</code> API. And if you're still adding <code class="inline-code">moment.js</code> (72 KB minified + locale data) or <code class="inline-code">date-fns</code> (12 KB per function) to format dates, you're shipping code the browser already runs faster.
</p>

<p class="post-p">
Let's fix that.
</p>

<h2 class="post-h2">Why Intl Beats Libraries</h2>

<p class="post-p">
| Concern | Library (moment, date-fns, etc.) | Intl API |
|---|---|---|
| <strong>Bundle size</strong> | 12–232 KB + locale data | 0 bytes (native) |
| <strong>Performance</strong> | JavaScript VM | Native C++ engine |
| <strong>Locale coverage</strong> | What you import | 400+ locales built in |
| <strong>Consistency</strong> | Library conventions | ECMA-402 standard |
| <strong>Tree-shaking</strong> | Ineffective for locale data | Not needed |
| <strong>Maintenance</strong> | Regular breaking changes | Stable, evergreen |
</p>

<p class="post-p">
The <code class="inline-code">Intl</code> API is defined by the ECMA-402 specification and has been <strong>Baseline since 2019</strong>. Chrome, Firefox, Safari, Edge — it's everywhere. Here's everything you can do with it.
</p>

<h2 class="post-h2">1. Intl.DateTimeFormat — Format Any Date, Any Locale</h2>

<p class="post-p">
This is the one most developers have seen but never fully explored. It goes far beyond <code class="inline-code">toLocaleDateString()</code>.
</p>

<h3 class="post-h3">Basic Usage</h3>

<pre class="code-block"><code class="language-javascript">const date = new Date('2026-05-30T14:30:00Z');

<p class="post-p">
// Default locale
new Intl.DateTimeFormat('en-US').format(date);
// → "5/30/2026"
</p>

<p class="post-p">
// Different locale
new Intl.DateTimeFormat('de-DE').format(date);
// → "30.5.2026"
</p>

<p class="post-p">
new Intl.DateTimeFormat('ja-JP').format(date);
// → "2026/5/30"
</code></pre>
</p>

<h3 class="post-h3">Date/Time Style Presets</h3>

<p class="post-p">
The <code class="inline-code">dateStyle</code> and <code class="inline-code">timeStyle</code> options give you common presets without manually specifying each component:
</p>

<pre class="code-block"><code class="language-javascript">const dt = new Date('2026-05-30T14:30:00Z');

<p class="post-p">
// Date styles
new Intl.DateTimeFormat('en-US', { dateStyle: 'full' }).format(dt);
// → "Saturday, May 30, 2026"
</p>

<p class="post-p">
new Intl.DateTimeFormat('en-US', { dateStyle: 'long' }).format(dt);
// → "May 30, 2026"
</p>

<p class="post-p">
new Intl.DateTimeFormat('en-US', { dateStyle: 'medium' }).format(dt);
// → "May 30, 2026"
</p>

<p class="post-p">
new Intl.DateTimeFormat('en-US', { dateStyle: 'short' }).format(dt);
// → "5/30/26"
</p>

<p class="post-p">
// Time styles
new Intl.DateTimeFormat('en-US', { timeStyle: 'full' }).format(dt);
// → "2:30:00 PM Coordinated Universal Time"
</p>

<p class="post-p">
new Intl.DateTimeFormat('en-US', { timeStyle: 'short' }).format(dt);
// → "2:30 PM"
</code></pre>
</p>

<h3 class="post-h3">Custom Components</h3>

<p class="post-p">
Need specific control? Use the component options:
</p>

<pre class="code-block"><code class="language-javascript">new Intl.DateTimeFormat('en-US', {
<p class="post-p">
weekday: 'long',
year: 'numeric',
month: 'long',
day: 'numeric',
hour: 'numeric',
minute: '2-digit',
timeZoneName: 'short'
}).format(new Date());
// → "Saturday, May 30, 2026 at 2:30 PM UTC"
</code></pre>
</p>

<h3 class="post-h3">Time Zones</h3>

<p class="post-p">
This is one of the most powerful features — handle any IANA timezone with zero dependencies:
</p>

<pre class="code-block"><code class="language-javascript">// Display a date in Tokyo time
<p class="post-p">
new Intl.DateTimeFormat('en-US', {
dateStyle: 'full',
timeStyle: 'long',
timeZone: 'Asia/Tokyo'
}).format(new Date());
// → "Saturday, May 30, 2026 at 11:30:00 PM JST"
</p>

<p class="post-p">
// Useful utility: get the user's timezone
const userTimezone = Intl.DateTimeFormat().resolvedOptions().timeZone;
console.log(userTimezone); // → "America/New_York" (or whatever)
</code></pre>
</p>

<h3 class="post-h3">Calendar Systems</h3>

<p class="post-p">
Beyond Gregorian — support for Islamic, Hebrew, Buddhist, Chinese, and others:
</p>

<pre class="code-block"><code class="language-javascript">// Islamic calendar
<p class="post-p">
new Intl.DateTimeFormat('ar-SA-u-ca-islamic', { dateStyle: 'full' }).format(new Date());
// Arabic rendering of the Islamic date
</p>

<p class="post-p">
// Japanese imperial calendar
new Intl.DateTimeFormat('ja-JP-u-ca-japanese', { dateStyle: 'long' }).format(new Date());
// → "令和8年5月30日"
</code></pre>
</p>

<h3 class="post-h3">Relative Time with formatRange</h3>

<p class="post-p">
Display date ranges naturally:
</p>

<pre class="code-block"><code class="language-javascript">const start = new Date('2026-05-30');
<p class="post-p">
const end = new Date('2026-06-05');
</p>

<p class="post-p">
new Intl.DateTimeFormat('en-US', {
month: 'short',
day: 'numeric'
}).formatRange(start, end);
// → "May 30 – Jun 5, 2026"
</code></pre>
</p>

<h2 class="post-h2">2. Intl.NumberFormat — Beyond Basic Number Display</h2>

<h3 class="post-h3">Locale-Aware Numbers</h3>

<pre class="code-block"><code class="language-javascript">const n = 1234567.89;

new Intl.NumberFormat('ar-EG').format(n);  // → "١٬٢٣٤٬٥٦٧٫٨٩"
new Intl.NumberFormat('hi-IN').format(n);  // → "12,34,567.89"  (Indian numbering!)
</code></pre>
</p>

<h3 class="post-h3">Currency Formatting</h3>

</p>

<p class="post-p">

</p>

<p class="post-p">

</code></pre>
</p>

<h3 class="post-h3">Percentages and Compact Notation</h3>

<h2 class="post-h2">3. Intl.RelativeTimeFormat — "3 Days Ago" Without a Library</h2>

<p class="post-p">
This is the cleanest way to display relative timestamps:
</p>

<pre class="code-block"><code class="language-javascript">const rtf = new Intl.RelativeTimeFormat('en', { numeric: 'auto' });

<p class="post-p">
rtf.format(-1, 'day');    // → "yesterday"
rtf.format(-2, 'day');    // → "2 days ago"
rtf.format(1, 'day');     // → "tomorrow"
rtf.format(0, 'day');     // → "today"
rtf.format(-3, 'week');   // → "3 weeks ago"
rtf.format(5, 'minute');  // → "in 5 minutes"
rtf.format(-1, 'hour');   // → "1 hour ago"
</p>

<p class="post-p">
// Always-numeric style (never shows "yesterday"/"tomorrow")
const rtfNum = new Intl.RelativeTimeFormat('en', { numeric: 'always' });
rtfNum.format(-1, 'day'); // → "1 day ago"
rtfNum.format(1, 'day');  // → "in 1 day"
</p>

<p class="post-p">
// Other locales
new Intl.RelativeTimeFormat('de', { numeric: 'auto' }).format(-1, 'day');
// → "gestern"
</p>

<p class="post-p">
new Intl.RelativeTimeFormat('fr', { numeric: 'auto' }).format(-1, 'day');
// → "hier"
</p>

<p class="post-p">
new Intl.RelativeTimeFormat('ja', { numeric: 'auto' }).format(-1, 'day');
// → "昨日"
</code></pre>
</p>

<h3 class="post-h3">Building a "Time Ago" Function</h3>

<pre class="code-block"><code class="language-javascript">function timeAgo(date) {
<p class="post-p">
const now = new Date();
const diff = date - now; // milliseconds
const seconds = Math.round(diff / 1000);
const minutes = Math.round(seconds / 60);
const hours = Math.round(minutes / 60);
const days = Math.round(hours / 24);
const weeks = Math.round(days / 7);
const months = Math.round(days / 30);
const years = Math.round(days / 365);
</p>

<p class="post-p">
const rtf = new Intl.RelativeTimeFormat('en', { numeric: 'auto' });
</p>

<p class="post-p">
if (Math.abs(years) &amp;gt;= 1) return rtf.format(years, 'year');
if (Math.abs(months) &amp;gt;= 1) return rtf.format(months, 'month');
if (Math.abs(weeks) &amp;gt;= 1) return rtf.format(weeks, 'week');
if (Math.abs(days) &amp;gt;= 1) return rtf.format(days, 'day');
if (Math.abs(hours) &amp;gt;= 1) return rtf.format(hours, 'hour');
if (Math.abs(minutes) &amp;gt;= 1) return rtf.format(minutes, 'minute');
return rtf.format(seconds, 'second');
}
</p>

<p class="post-p">
timeAgo(new Date('2026-05-29')); // → "yesterday"
timeAgo(new Date('2026-05-20')); // → "last week"
timeAgo(new Date('2026-06-05')); // → "next week"
</code></pre>
</p>

<p class="post-p">
No <code class="inline-code">moment</code>, no <code class="inline-code">date-fns</code>, no <code class="inline-code">dayjs</code>. Zero dependencies.
</p>

<h2 class="post-h2">4. Intl.ListFormat — Natural Language Lists</h2>

<p class="post-p">
Format arrays of strings into natural-language lists:
</p>

<pre class="code-block"><code class="language-javascript">const items = ['React', 'Vue', 'Svelte'];

<p class="post-p">
// Conjunction (default — "and" style)
new Intl.ListFormat('en').format(items);
// → "React, Vue, and Svelte"
</p>

<p class="post-p">
// Disjunction ("or" style)
new Intl.ListFormat('en', { type: 'disjunction' }).format(items);
// → "React, Vue, or Svelte"
</p>

<p class="post-p">
// Unit (no conjunction — just separators)
new Intl.ListFormat('en', { type: 'unit' }).format(items);
// → "React, Vue, Svelte"
</p>

<p class="post-p">
// With style options
new Intl.ListFormat('en', {
style: 'long',
type: 'conjunction'
}).format(items);
// → "React, Vue, and Svelte"
</p>

<p class="post-p">
new Intl.ListFormat('en', {
style: 'short',
type: 'conjunction'
}).format(items);
// → "React, Vue, &amp;amp; Svelte"
</p>

<p class="post-p">
new Intl.ListFormat('en', {
style: 'narrow',
type: 'conjunction'
}).format(items);
// → "React, Vue, Svelte"
</code></pre>
</p>

<p class="post-p">
Different languages have entirely different list patterns:
</p>

<pre class="code-block"><code class="language-javascript">new Intl.ListFormat('ja').format(['JavaScript', 'CSS', 'HTML']);
<p class="post-p">
// → "JavaScript、CSS、HTML"
</p>

<p class="post-p">
new Intl.ListFormat('es').format(['JavaScript', 'CSS', 'HTML']);
// → "JavaScript, CSS y HTML"
</p>

<p class="post-p">
new Intl.ListFormat('zh').format(['JavaScript', 'CSS', 'HTML']);
// → "JavaScript、CSS和HTML"
</code></pre>
</p>

<h2 class="post-h2">5. Intl.PluralRules — Never Hardcode Pluralization Again</h2>

<pre class="code-block"><code class="language-javascript">const pr = new Intl.PluralRules('en-US');

<p class="post-p">
pr.select(0);   // → "other"   ("0 items")
pr.select(1);   // → "one"     ("1 item")
pr.select(2);   // → "other"   ("2 items")
</p>

<p class="post-p">
// Different languages have different plural categories
const arabic = new Intl.PluralRules('ar');
arabic.select(0);   // → "zero"
arabic.select(1);   // → "one"
arabic.select(2);   // → "two"
arabic.select(3);   // → "few"
arabic.select(11);  // → "many"
</p>

<p class="post-p">
// Russian has four categories
const russian = new Intl.PluralRules('ru');
russian.select(1);   // → "one"    (1 книга)
russian.select(2);   // → "few"    (2 книги)
russian.select(5);   // → "many"   (5 книг)
russian.select(21);  // → "one"    (21 книга — Russian plural rules!)
</code></pre>
</p>

<h3 class="post-h3">Combining with Ordinals</h3>

<pre class="code-block"><code class="language-javascript">const pr = new Intl.PluralRules('en', { type: 'ordinal' });

<p class="post-p">
pr.select(1);   // → "one"   → "1st"
pr.select(2);   // → "two"   → "2nd"
pr.select(3);   // → "few"   → "3rd"
pr.select(4);   // → "other" → "4th"
pr.select(21);  // → "one"   → "21st"
pr.select(22);  // → "two"   → "22nd"
</code></pre>
</p>

<h3 class="post-h3">Building a Plural-Aware Message System</h3>

<pre class="code-block"><code class="language-javascript">const messages = {
<p class="post-p">
en: {
item: {
one: 'You have 1 item',
other: 'You have {count} items'
}
},
ru: {
item: {
one: 'У вас {count} предмет',    // 1, 21, 31...
few: 'У вас {count} предмета',   // 2-4, 22-24...
many: 'У вас {count} предметов'  // 5-20, 25-30...
}
}
};
</p>

<p class="post-p">
function pluralMessage(count, locale = 'en') {
const pr = new Intl.PluralRules(locale);
const category = pr.select(count);
const template = messages[locale]?.item?.[category] ?? messages[locale]?.item?.other;
return template.replace('{count}', count);
}
</p>

<p class="post-p">
pluralMessage(1, 'ru');   // → "У вас 1 предмет"
pluralMessage(2, 'ru');   // → "У вас 2 предмета"
pluralMessage(5, 'ru');   // → "У вас 5 предметов"
pluralMessage(21, 'ru');  // → "У вас 21 предмет" (correctly!)
</code></pre>
</p>

<h2 class="post-h2">6. Intl.Collator — Locale-Aware String Sorting</h2>

<p class="post-p">
The default JavaScript sort is lexicographic and locale-ignorant. <code class="inline-code">Intl.Collator</code> fixes this:
</p>

<pre class="code-block"><code class="language-javascript">const names = ['Özil', 'Müller', 'Álvarez', 'Smith', 'Zhang'];

<p class="post-p">
// Naive sort (wrong for accented characters)
names.sort();
// → ["Müller", "Smith", "Zhang", "Álvarez", "Özil"] — wrong!
</p>

<p class="post-p">
// Collator sort
const collator = new Intl.Collator('en');
names.sort(collator.compare);
// → ["Álvarez", "Müller", "Özil", "Smith", "Zhang"] — correct!
</p>

<p class="post-p">
// Case-insensitive
const ciCollator = new Intl.Collator('en', { sensitivity: 'base' });
['a', 'B', 'c', 'D'].sort(ciCollator.compare);
// → ["a", "B", "c", "D"]
</p>

<p class="post-p">
// Numeric sorting
const numCollator = new Intl.Collator('en', { numeric: true });
['file10.txt', 'file2.txt', 'file1.txt'].sort(numCollator.compare);
// → ["file1.txt", "file2.txt", "file10.txt"] — natural sort!
</code></pre>
</p>

<h2 class="post-h2">8. Intl.Segmenter — Word, Sentence, and Grapheme Segmentation</h2>

<p class="post-p">
Segmentation is deceptively hard. Splitting by spaces fails for CJK languages. Splitting by graphemes is essential for emoji (which can span multiple code points). <code class="inline-code">Intl.Segmenter</code> handles it all:
</p>

<pre class="code-block"><code class="language-javascript">const segmenter = new Intl.Segmenter('en', { granularity: 'word' });
<p class="post-p">
const text = 'The Intl API is 👨‍👩‍👧‍👦 awesome!';
</p>

<p class="post-p">
[...segmenter.segment(text)].map(s =&amp;gt; s.segment);
// → ["The", " ", "Intl", " ", "API", " ", "is", " ", "👨‍👩‍👧‍👦", " ", "awesome", "!"]
</p>

<p class="post-p">
// Grapheme segmentation (handles complex emoji correctly)
const grapheme = new Intl.Segmenter('en', { granularity: 'grapheme' });
[...grapheme.segment('👨‍👩‍👧‍👦')];
// → [{ segment: "👨‍👩‍👧‍👦", index: 0, input: "👨‍👩‍👧‍👦" }]
// One segment — not 7! The ZWJ sequence is a single grapheme.
</p>

<p class="post-p">
// Sentence segmentation
const sentence = new Intl.Segmenter('en', { granularity: 'sentence' });
const text2 = 'Hello world! How are you? I am fine.';
[...sentence.segment(text2)].map(s =&amp;gt; s.segment);
// → ["Hello world! ", "How are you? ", "I am fine."]
</code></pre>
</p>

<h2 class="post-h2">9. Intl.DurationFormat (Stage 3 — Coming Soon)</h2>

<pre class="code-block"><code class="language-javascript">// Future syntax (not yet available in all browsers)

// Short style
df.format({ hours: 1, minutes: 30 }, { style: 'short' });
// → "1 hr, 30 min"
</p>

<p class="post-p">
// Digital clock style
df.format({ hours: 1, minutes: 30, seconds: 5 }, { style: 'digital' });
// → "1:30:05"
</code></pre>

</p>

<h2 class="post-h2">Performance: How Much Faster Is Intl?</h2>

<p class="post-p">
The Intl API runs in native C++ inside the browser engine — it doesn't touch the JavaScript VM for core formatting work. For high-volume operations, the difference is dramatic:
</p>

<p class="post-p">
| Operation | Library (date-fns) | Intl API | Speedup |
|---|---|---|---|
| 10,000 date formats | ~180ms | ~8ms | <strong>22x</strong> |
| 10,000 number formats | ~15ms (numeral.js) | ~2ms | <strong>7.5x</strong> |
| 10,000 list formats | ~25ms (manual) | ~3ms | <strong>8x</strong> |
</p>

<p class="post-p">
The library overhead adds up fast when you're rendering server-side lists, generating reports, or formatting large datasets.
</p>

<h2 class="post-h2">Putting It All Together: A Production-Ready Utility Module</h2>

<p class="post-p">
Here's a complete utility module you can drop into any project — no dependencies needed:
</p>

<pre class="code-block"><code class="language-javascript">// utils/format.js — zero-dependency formatting utilities
<p class="post-p">
export const formatDate = (date, locale = 'en-US', options = { dateStyle: 'medium' }) =&amp;gt;
new Intl.DateTimeFormat(locale, options).format(new Date(date));
</p>

<p class="post-p">
export const formatNumber = (num, locale = 'en-US', options = {}) =&amp;gt;
new Intl.NumberFormat(locale, options).format(num);
</p>

<p class="post-p">
export const formatCurrency = (amount, currency = 'USD', locale = 'en-US') =&amp;gt;
new Intl.NumberFormat(locale, { style: 'currency', currency }).format(amount);
</p>

<p class="post-p">
export const formatCompact = (num, locale = 'en-US') =&amp;gt;
new Intl.NumberFormat(locale, { notation: 'compact' }).format(num);
</p>

<p class="post-p">
export const formatPercent = (ratio, locale = 'en-US', digits = 1) =&amp;gt;
new Intl.NumberFormat(locale, {
style: 'percent',
minimumFractionDigits: digits,
maximumFractionDigits: digits
}).format(ratio);
</p>

<p class="post-p">
export const formatList = (items, locale = 'en-US', type = 'conjunction') =&amp;gt;
new Intl.ListFormat(locale, { style: 'long', type }).format(items);
</p>

<p class="post-p">
export const timeAgo = (date, locale = 'en-US') =&amp;gt; {
const rtf = new Intl.RelativeTimeFormat(locale, { numeric: 'auto' });
const diff = date - new Date();
const units = [
{ unit: 'year', seconds: 31536000 },
{ unit: 'month', seconds: 2592000 },
{ unit: 'week', seconds: 604800 },
{ unit: 'day', seconds: 86400 },
{ unit: 'hour', seconds: 3600 },
{ unit: 'minute', seconds: 60 },
{ unit: 'second', seconds: 1 }
];
</p>

<p class="post-p">
const seconds = Math.round(diff / 1000);
for (const { unit, seconds: unitSeconds } of units) {
const value = Math.round(seconds / unitSeconds);
if (Math.abs(value) &amp;gt;= 1) {
return rtf.format(value, unit);
}
}
return rtf.format(0, 'second');
};
</p>

<p class="post-p">
export const sortLocale = (arr, locale = 'en-US', options = {}) =&amp;gt; {
const collator = new Intl.Collator(locale, options);
return [...arr].sort(collator.compare);
};
</p>

<p class="post-p">
export const pluralize = (count, forms, locale = 'en-US') =&amp;gt; {
const pr = new Intl.PluralRules(locale);
const category = pr.select(count);
return forms[category] || forms.other || '';
};
</p>

<p class="post-p">
// Usage:
formatCurrency(1234.56, 'EUR', 'de-DE');  // → "1.234,56 €"
timeAgo(new Date('2026-05-29'));           // → "yesterday"
formatList(['HTML', 'CSS', 'JS']);         // → "HTML, CSS, and JS"
sortLocale(['Özil', 'Álvarez', 'Smith']);  // → ["Álvarez", "Özil", "Smith"]
</code></pre>
</p>

<h2 class="post-h2">When You Still Need a Library</h2>

<p class="post-p">
The Intl API covers 95% of formatting needs, but there are edge cases where libraries help:
</p>

<ul class="post-ul"><li class="post-li"><strong>Time zone math</strong> (adding/subtracting across DST boundaries) — use <code class="inline-code">luxon</code> or <code class="inline-code">date-fns-tz</code></li>
<li class="post-li"><strong>Parsing arbitrary date strings</strong> — <code class="inline-code">Intl</code> doesn't parse, it only formats</li>
<li class="post-li"><strong>Non-Gregorian calendar manipulation</strong> — libraries provide conversion utilities</li>
<li class="post-li"><strong>ICU MessageFormat</strong> — complex interpolation with gender, selectors, etc.</li>
</ul>
<p class="post-p">
For everything else — dates, numbers, currencies, lists, plurals, sorting, segmentation — the platform has you covered.
</p>

<h2 class="post-h2">The Bottom Line</h2>

<p class="post-p">
Every time you add a dependency, you add a maintenance burden, a security surface, and bytes to your bundle. The <code class="inline-code">Intl</code> API removes all three for one of the most common categories of frontend work: formatting and localization.
</p>

<p class="post-p">
Next time you're about to <code class="inline-code">npm install</code> a formatting library, ask yourself: "Does Intl already do this?" The answer is probably yes.
