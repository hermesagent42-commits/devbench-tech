CSS linear() Easing: Build Bounce, Spring, and Elastic Curves Without JavaScript

The CSS linear() easing function lets you define multi-stop easing curves with exact value-at-time control. Build bounce, spring, elastic, and custom easing directly in CSS — no cubic-bezier() limitations, no JavaScript animation libraries. Complete guide with 12 production-ready presets, visual comparison charts, performance deep-dive, and a curated cheatsheet.

15 Years of cubic-bezier() — And Its One Fatal Flaw

Every animation you've ever written in CSS has been held hostage by cubic-bezier(). Four numbers. Two control points. If the easing you wanted didn't fit within those constraints, you reached for JavaScript — GSAP, Framer Motion, anime.js, your own requestAnimationFrame loop. Not anymore. CSS linear() is the easing function that gives you unlimited control points, letting you specify the exact progress at any point in time.

The problem: a cubic Bézier curve can only have one inflection point. That means no bounce. No spring oscillation. No elastic overshoot-and-settle. The cubic-bezier(0.34, 1.56, 0.64, 1) "bounce" is a single overshoot — not the multi-bounce you get from a real physics simulation.

If you've ever built anything that needed genuine bounce, spring, or a custom motion profile, you've felt this limitation. linear() ends it.

How linear() Works

The linear() easing function accepts a comma-separated list of stops — each one says "at this percentage of time, progress should be at this percentage." You can have as many stops as you want. 

/* Basic syntax — evenly spaced stops */
transition-timing-function: linear(0, 0.25, 0.5, 0.75, 1);
/*                               ↑  ↑      ↑     ↑      ↑
                              stops at 0%, 25%, 50%, 75%, 100% */

/* With explicit input percentages */
transition-timing-function: linear(
  0 0%,       /* at 0% of time, progress is 0% */
  0.5 10%,    /* at 10% of time, progress is 50% */
  1 80%,      /* at 80% of time, progress is 100% — stay there */
  0.8 85%,    /* at 85% of time, progress drops to 80% — overshoot! */
  1 100%      /* finally settle at 100% */
);

Each stop is <output> <input>? — where input is the percentage of duration and output is the progress at that point. Stops without input percentages are spaced evenly. The browser linearly interpolates between consecutive stops — guaranteed O(log n) performance.

Unlike cubic-bezier() which requires solving a cubic equation, linear() is piecewise linear interpolation: sort stops, find the two that bracket the current time, lerp between them. It's dead simple math.

Real-World Use Cases

Notification entrance with spring

.notification {
  animation: notificationEnter 0.6s var(--ease-spring) both;
}

@keyframes notificationEnter {
  from {
    transform: translateX(100%) scale(0.8);
    opacity: 0;
  }
  to {
    transform: translateX(0) scale(1);
    opacity: 1;
  }
}

Dialog backdrop with emphatic easing

.dialog-overlay {
  animation: overlayFade 0.3s var(--ease-emphatic);
}

@keyframes overlayFade {
  from { opacity: 0; }
  to   { opacity: 1; }
}

Error shake for form validation

.input-error {
  animation: shake 0.5s var(--ease-shake);
}

@keyframes shake {
  0%, 100% { transform: translateX(0); }
}

The easing handles the oscillation — the keyframe just declares the start/end. Combine var(--ease-shake) with a simple translateX keyframe and you get a professional shake animation with zero JavaScript.

Loading skeleton pulse

.skeleton {
  animation: pulse 1.5s var(--ease-emphatic) infinite;
}

@keyframes pulse {
  0%, 100% { opacity: 0.5; }
  50%      { opacity: 1; }
}

Card hover bounce

.card {
  transition: transform 0.4s var(--ease-bounce);
}

.card:hover {
  transform: scale(1.03);
}

That's right — linear() works in transition-timing-function too. Not just @keyframes.

ComplexityO(1) per frameO(log n) per frame
Max control points4 (two anchors, two handles)Unlimited

Sweet spot: 5–30 stops for bounce and spring curves. Above 30 stops, the visual difference is imperceptible — piecewise linear curves converge to smoothness quickly.

Progressive Enhancement

linear() reached Baseline in early 2025. Chrome 127+, Firefox 126+, Safari 17.2+, Edge 127+. Global coverage: ~96%. But if you need to support older browsers: 

/* Fallback: regular ease for old browsers */
.my-element {
  animation: slideUp 0.5s ease-out;
}

/* Enhancement: spring for modern browsers */
@supports (animation-timing-function: linear(0, 1)) {
  .my-element {
    animation: slideUp 0.5s var(--ease-spring);
  }
}

The @supports check detects linear() support cleanly. In unsupported browsers, the animation still plays — just without the spring effect.

Combining linear() with animation-composition

CSS animation-composition (also Baseline 2026) lets multiple animations combine on the same property. Pair it with linear() for compound effects: 

.floating-card {
  animation:
    float 3s linear(0, 0.5 50%, 1 100%) infinite,
    shadow 3s var(--ease-emphatic) infinite;
  animation-composition: accumulate;
}

@keyframes float {
  from, to { transform: translateY(0); }
  50%      { transform: translateY(-12px); }
}

@keyframes shadow {
  from, to { box-shadow: 0 2px 8px rgba(0,0,0,0.15); }
  50%      { box-shadow: 0 12px 24px rgba(0,0,0,0.2); }
}

When NOT to Use linear()

  • Default state transitions: A simple fade doesn't need a 50-stop easing. Use ease, ease-out, or a 3-stop linear().
  • Continuous infinite animations: If an animation runs forever (e.g., rotating loader), the easing only matters at the start. Use linear (the keyword, not the function).
  • Physics-accurate simulation: linear() approximates spring/bounce curves. For game physics, use a JS physics engine + rAF.
  • Hundreds of simultaneous elements: While linear() is fast, cubic-bezier() is still slightly faster per-frame. For 500+ concurrent animated elements, consider simpler easings.

The Bottom Line

For 15 years, CSS animations have been constrained by cubic-bezier() — four numbers, one inflection point, and a whole lot of JavaScript workarounds for anything more complex. linear() changes that.

You can now define bounce. Spring. Elastic. Shake. Squash-and-stretch. Smooth stepped progressions. Anticipated movements. All in CSS, all GPU-accelerated, all running at 60fps with no JavaScript.

The 12 curves in this guide cover 90% of motion design patterns. Copy them into your :root as CSS custom properties, use them in your animation shorthand, and never touch a JavaScript easing library again for UI animations.

linear() is the last easing function CSS will ever need.
