<h2 class="post-h2">What Is HTMX?</h2>

<p class="post-p">
HTMX is a small (~14 KB gzipped) JavaScript library that gives you access to AJAX, CSS Transitions, WebSockets, and Server-Sent Events directly in HTML — using attributes rather than JavaScript. Instead of writing <code class="inline-code">fetch()</code> calls and DOM manipulations, you add attributes like <code class="inline-code">hx-get</code>, <code class="inline-code">hx-target</code>, and <code class="inline-code">hx-swap</code> to your HTML elements.
</p>

<pre class="code-block"><code class="language-html">&amp;lt;button hx-post="/api/like" hx-target="#like-count" hx-swap="innerHTML"&amp;gt;
<p class="post-p">
👍 Like
&amp;lt;/button&amp;gt;
&amp;lt;span id="like-count"&amp;gt;42&amp;lt;/span&amp;gt;
</code></pre>
</p>

<p class="post-p">
That's it. When clicked, HTMX POSTs to <code class="inline-code">/api/like</code>, takes the response HTML, and swaps it into <code class="inline-code">#like-count</code>. No <code class="inline-code">fetch()</code>, no <code class="inline-code">innerHTML =</code>, no state management — it reuses the server-rendered HTML that your backend already produces.
</p>

<h2 class="post-h2">The Renaissance</h2>

<p class="post-p">
In 2026, HTMX has reached a cultural tipping point:
</p>

<ul class="post-ul"><li class="post-li"><strong>GitHub stars</strong>: HTMX has surpassed React, Vue, and Svelte in total stars — a signal of developer enthusiasm that no framework has matched</li>
<li class="post-li"><strong>Hacker News</strong>: You can barely read a web development thread without finding HTMX in the comments</li>
<li class="post-li"><strong>"Frontend Minimalism"</strong>: A growing movement of developers rejecting heavy SPA frameworks in favor of hypermedia-driven architecture</li>
</ul>
<p class="post-p">
The appeal is straightforward: server-side rendering works. You already have templates. You already have routing. You already handle state on the server. HTMX lets you build interactive UIs without duplicating all that logic in JavaScript.
</p>

<h2 class="post-h2">The Complete HTMX Attribute System</h2>

<p class="post-p">
HTMX has a rich attribute vocabulary. Here are the essentials:
</p>

<h3 class="post-h3">Core Request Attributes</h3>

<ul class="post-ul"><li class="post-li"><code class="inline-code">hx-get</code>, <code class="inline-code">hx-post</code>, <code class="inline-code">hx-put</code>, <code class="inline-code">hx-patch</code>, <code class="inline-code">hx-delete</code> — Issue HTTP requests on trigger events</li>
</ul>
<h3 class="post-h3">Targeting &amp; Swapping</h3>

<ul class="post-ul"><li class="post-li"><code class="inline-code">hx-target</code> — CSS selector for which element receives the response</li>
<li class="post-li"><code class="inline-code">hx-swap</code> — How the response is placed: <code class="inline-code">innerHTML</code>, <code class="inline-code">outerHTML</code>, <code class="inline-code">beforebegin</code>, <code class="inline-code">afterend</code>, etc.</li>
<li class="post-li"><code class="inline-code">hx-swap-oob</code> — "Out-of-band" swaps: update elements anywhere on the page in one request</li>
</ul>
<h3 class="post-h3">Triggers</h3>

<ul class="post-ul"><li class="post-li"><code class="inline-code">hx-trigger</code> — The most powerful attribute. Control what event fires the request, with modifiers like <code class="inline-code">delay</code>, <code class="inline-code">throttle</code>, <code class="inline-code">once</code>, <code class="inline-code">from:</code>, <code class="inline-code">every 2s</code>, <code class="inline-code">revealed</code>, and <code class="inline-code">load</code></li>
<li class="post-li"><code class="inline-code">hx-on</code> — Inline event handlers for any HTMX lifecycle event</li>
</ul>
<h3 class="post-h3">Request Configuration</h3>

<ul class="post-ul"><li class="post-li"><code class="inline-code">hx-params</code>, <code class="inline-code">hx-vals</code>, <code class="inline-code">hx-include</code> — Control which data gets sent</li>
<li class="post-li"><code class="inline-code">hx-headers</code> — Add custom HTTP headers</li>
<li class="post-li"><code class="inline-code">hx-ext</code> — Enable HTMX extensions (JSON encoding, WebSockets, SSE)</li>
</ul>
<h3 class="post-h3">History</h3>

<ul class="post-ul"><li class="post-li"><code class="inline-code">hx-push-url</code>, <code class="inline-code">hx-replace-url</code> — Update the browser URL bar</li>
<li class="post-li"><code class="inline-code">hx-boost</code> — Progressively enhance all links and forms to use AJAX (one attribute on <code class="inline-code">&lt;body&gt;</code> gives you SPA-like navigation)</li>
</ul>
<h3 class="post-h3">UX</h3>

<ul class="post-ul"><li class="post-li"><code class="inline-code">hx-indicator</code> — Show a loading spinner during requests</li>
<li class="post-li"><code class="inline-code">hx-confirm</code>, <code class="inline-code">hx-prompt</code> — Ask for confirmation or user input before firing</li>
<li class="post-li"><code class="inline-code">hx-validate</code> — Enforce HTML5 form validation before requests</li>
<li class="post-li"><code class="inline-code">hx-swap-oob</code> — Update multiple unrelated sections in one response</li>
</ul>
<h2 class="post-h2">When NOT to Use HTMX</h2>

<p class="post-p">
HTMX is not for every project. It works best when:
</p>

<ul class="post-ul"><li class="post-li">Your backend renders HTML (Django, Rails, Laravel, Phoenix, Go templates, etc.)</li>
<li class="post-li">Most of your interactivity is server-driven (form submissions, search, navigation)</li>
<li class="post-li">You don't need complex client-side state management</li>
</ul>
<p class="post-p">
It's not ideal for:
</p>

<ul class="post-ul"><li class="post-li">Highly interactive client-side apps (Figma, Google Sheets)</li>
<li class="post-li">Offline-first applications</li>
<li class="post-li">Teams that have already invested heavily in React/Vue/Svelte component libraries</li>
</ul>

<p class="post-p">

It's organized by category (Core, Swap, Triggers, Config, Loading, History, Confirm) and fully searchable.
</p>
