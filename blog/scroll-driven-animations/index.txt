<p class="post-p">
Scroll-driven animations are one of the most exciting CSS features to ship in years. Instead of driving animations by time — a ticking clock — you drive them by <strong>scroll position</strong>. The animation progresses as the user scrolls through a container.
</p>

<p class="post-p">
As of late 2025, scroll-driven animations are <strong>Baseline</strong> across Chrome, Firefox, Safari, and Edge. No JavaScript needed. No Intersection Observer hacks. Just CSS.
</p>

<h2 class="post-h2">The Two Flavors of Scroll-Driven Animation</h2>

<p class="post-p">
CSS provides two ways to tie animation to scroll:
</p>

<h3 class="post-h3">1. <code class="inline-code">scroll-timeline</code> — The Animation Timeline Itself</h3>

<p class="post-p">
Instead of <code class="inline-code">animation-duration</code>, you set <code class="inline-code">animation-timeline: scroll()</code>. The animation duration becomes the scrollable range of an element.
</p>

<pre class="code-block"><code class="language-css">.reveal-image {
<p class="post-p">
animation: fade-in linear;
animation-timeline: scroll(root);
}
</p>

<p class="post-p">
@keyframes fade-in {
from { opacity: 0; transform: translateY(40px); }
to   { opacity: 1; transform: translateY(0); }
}
</code></pre>
</p>

<p class="post-p">
As the user scrolls the page from top to bottom, the image fades in over the <em>entire scroll range</em>. No JavaScript.
</p>

<h3 class="post-h3">2. <code class="inline-code">view-timeline</code> — Triggered by Element Visibility</h3>

<p class="post-p">
With <code class="inline-code">view()</code> timelines, the animation runs as an element <em>enters and exits</em> the scrollport.
</p>

<pre class="code-block"><code class="language-css">.card {
<p class="post-p">
animation: enter-card linear;
animation-timeline: view();
animation-range: entry 0% cover 40%;
}
</p>

<p class="post-p">
@keyframes enter-card {
from {
opacity: 0;
transform: translateY(60px) scale(0.95);
}
to {
opacity: 1;
transform: translateY(0) scale(1);
}
}
</code></pre>
</p>

<p class="post-p">
Each <code class="inline-code">.card</code> animates <em>independently</em> as it scrolls into view. No IntersectionObserver, no scroll event listeners.
</p>

<h2 class="post-h2">Anatomy of <code class="inline-code">scroll()</code> and <code class="inline-code">view()</code></h2>

<h3 class="post-h3"><code class="inline-code">scroll()</code> parameters</h3>

<pre class="code-block"><code class="language-text">animation-timeline: scroll(&amp;lt;scroller&amp;gt; &amp;lt;axis&amp;gt;);
<p class="post-p">
</code></pre>
</p>

<p class="post-p">
| Parameter | Options | Default |
|-----------|---------|---------|
| <code class="inline-code">&lt;scroller&gt;</code> | <code class="inline-code">nearest</code>, <code class="inline-code">root</code>, <code class="inline-code">self</code> | <code class="inline-code">nearest</code> |
| <code class="inline-code">&lt;axis&gt;</code> | <code class="inline-code">block</code>, <code class="inline-code">inline</code>, <code class="inline-code">x</code>, <code class="inline-code">y</code> | <code class="inline-code">block</code> |
</p>

<ul class="post-ul"><li class="post-li"><code class="inline-code">nearest</code> — the nearest ancestor that can scroll</li>
<li class="post-li"><code class="inline-code">root</code> — the document/viewport</li>
<li class="post-li"><code class="inline-code">self</code> — the element itself (must be scrollable)</li>
<li class="post-li"><code class="inline-code">block</code> / <code class="inline-code">y</code> — vertical scroll</li>
<li class="post-li"><code class="inline-code">inline</code> / <code class="inline-code">x</code> — horizontal scroll</li>
</ul>
<pre class="code-block"><code class="language-css">/<em> Drive animation by horizontal scroll of the nearest scroll container </em>/
<p class="post-p">
animation-timeline: scroll(nearest inline);
</code></pre>
</p>

<h3 class="post-h3"><code class="inline-code">view()</code> syntax</h3>

<pre class="code-block"><code class="language-text">animation-timeline: view(&amp;lt;axis&amp;gt; &amp;lt;inset&amp;gt;);
<p class="post-p">
</code></pre>
</p>

<p class="post-p">
| Parameter | Description | Default |
|-----------|-------------|---------|
| <code class="inline-code">&lt;axis&gt;</code> | <code class="inline-code">block</code>, <code class="inline-code">inline</code>, <code class="inline-code">x</code>, <code class="inline-code">y</code> | <code class="inline-code">block</code> |
| <code class="inline-code">&lt;inset&gt;</code> | Offsets from scrollport edges | <code class="inline-code">auto</code> (0) |
</p>

<pre class="code-block"><code class="language-css">/<em> Timeline driven by element visibility with 100px inset </em>/
<p class="post-p">
animation-timeline: view(block 100px);
</code></pre>
</p>

<p class="post-p">
The inset shrinks the "visible" area — useful for triggering animations slightly before or after the element enters the scrollport.
</p>

<h2 class="post-h2">Controlling Animation Range</h2>

<p class="post-p">
You don't have to use the full scroll range. <code class="inline-code">animation-range</code> lets you define exactly <em>which portion</em> of the scroll drives the animation.
</p>

<pre class="code-block"><code class="language-css">animation-range: entry 20% exit 80%;
<p class="post-p">
animation-range: contain 0% contain 100%;
</code></pre>
</p>

<h3 class="post-h3">Named range points</h3>

<p class="post-p">
| Name | Meaning |
|------|---------|
| <code class="inline-code">cover 0%</code> | Element's top edge touches bottom of scrollport |
| <code class="inline-code">cover 100%</code> | Element's bottom edge touches top of scrollport |
| <code class="inline-code">contain 0%</code> | Element is fully inside scrollport |
| <code class="inline-code">contain 100%</code> | Element is about to exit scrollport |
| <code class="inline-code">entry 0%</code> | Element starts entering scrollport |
| <code class="inline-code">entry 100%</code> | Element is fully visible |
| <code class="inline-code">exit 0%</code> | Element starts leaving scrollport |
| <code class="inline-code">exit 100%</code> | Element has fully left scrollport |
</p>

<p class="post-p">
You can combine these with percentages to create precisely-timed animations:
</p>

<pre class="code-block"><code class="language-css">/<em> Animate only when the element is entering </em>/
<p class="post-p">
animation-range: entry 0% entry 100%;
</p>

<p class="post-p">
/<em> Animate during the middle third of visibility </em>/
animation-range: cover 33% cover 66%;
</p>

<p class="post-p">
/<em> Staggered: 100px after entry starts, 200px before exit ends </em>/
animation-range: entry 100px exit -200px;
</code></pre>
</p>

<h2 class="post-h2">Named Timelines with <code class="inline-code">scroll-timeline-name</code></h2>

<p class="post-p">
For more control, you can name a timeline and reference it elsewhere:
</p>

<pre class="code-block"><code class="language-css">.scroll-container {
<p class="post-p">
scroll-timeline-name: --gallery-scroll;
scroll-timeline-axis: x;
overflow-x: auto;
}
</p>

<p class="post-p">
.gallery-item:nth-child(1) { animation-timeline: --gallery-scroll; }
.gallery-item:nth-child(2) { animation-timeline: --gallery-scroll; }
.gallery-item:nth-child(3) { animation-timeline: --gallery-scroll; }
</code></pre>
</p>

<p class="post-p">
All three items share the <strong>same</strong> timeline — they animate in lockstep as the container scrolls horizontally.
</p>

<h2 class="post-h2">Real-World Patterns</h2>

<h3 class="post-h3">Pattern 1: Reading Progress Bar</h3>

<p class="post-p">
A progress bar at the top of the page that fills as the user scrolls:
</p>

<pre class="code-block"><code class="language-css">.progress-bar {
<p class="post-p">
position: fixed;
top: 0;
left: 0;
height: 4px;
background: linear-gradient(to right, #6366f1, #ec4899);
transform-origin: left;
animation: grow linear;
animation-timeline: scroll(root);
}
</p>

<p class="post-p">
@keyframes grow {
from { transform: scaleX(0); }
to   { transform: scaleX(1); }
}
</code></pre>
</p>

<p class="post-p">
No JavaScript. No <code class="inline-code">scroll</code> event listener. No <code class="inline-code">requestAnimationFrame</code>. Just CSS.
</p>

<h3 class="post-h3">Pattern 2: Staggered Card Reveal</h3>

<p class="post-p">
Cards that fade in one-by-one as they scroll into view:
</p>

<pre class="code-block"><code class="language-css">.card {
<p class="post-p">
opacity: 0;
animation: reveal-card linear forwards;
animation-timeline: view();
animation-range: entry 5% entry 45%;
animation-delay: calc(var(--card-index) * 100ms);
}
</p>

<p class="post-p">
@keyframes reveal-card {
from { opacity: 0; transform: translateY(40px); }
to   { opacity: 1; transform: translateY(0); }
}
</code></pre>
</p>

<p class="post-p">
Each card reveals independently. The <code class="inline-code">--card-index</code> custom property staggers the delays. Zero JavaScript.
</p>

<h3 class="post-h3">Pattern 3: Parallax Effect</h3>

<pre class="code-block"><code class="language-css">.hero-image {
<p class="post-p">
animation: parallax linear;
animation-timeline: scroll(root);
animation-range: cover 0% cover 100%;
}
</p>

<p class="post-p">
@keyframes parallax {
from { transform: translateY(-20%); }
to   { transform: translateY(20%); }
}
</code></pre>
</p>

<p class="post-p">
The image scrolls at a different rate than the page — a classic parallax effect without any JavaScript.
</p>

<h3 class="post-h3">Pattern 4: Sticky Header Shrink</h3>

<p class="post-p">
A header that shrinks as you scroll down:
</p>

<pre class="code-block"><code class="language-css">.site-header {
<p class="post-p">
animation: shrink-header linear;
animation-timeline: scroll(root);
animation-range: 0px 200px;
}
</p>

<p class="post-p">
@keyframes shrink-header {
from {
padding: 24px 0;
background: transparent;
backdrop-filter: blur(0);
}
to {
padding: 12px 0;
background: rgba(15, 23, 42, 0.9);
backdrop-filter: blur(12px);
}
}
</code></pre>
</p>

<h3 class="post-h3">Pattern 5: Horizontal Scroll Gallery</h3>

<pre class="code-block"><code class="language-css">.gallery-track {
<p class="post-p">
display: flex;
overflow-x: auto;
scroll-timeline-name: --gallery;
scroll-timeline-axis: x;
}
</p>

<p class="post-p">
.gallery-caption {
animation: slide-captions linear;

}
</p>

<p class="post-p">

}
</code></pre>

<h2 class="post-h2">Performance: Why This Beats JavaScript</h2>

<p class="post-p">
Scroll-driven animations run on the <strong>compositor thread</strong>, not the main thread:
</p>

<ul class="post-ul"><li class="post-li"><strong>Zero main-thread jank</strong> — scrolling stays buttery smooth</li>
<li class="post-li"><strong>No <code class="inline-code">requestAnimationFrame</code></strong> — the browser handles everything natively</li>
<li class="post-li"><strong>Automatic off-main-thread compositing</strong> — GPU layer promotion</li>
<li class="post-li"><strong>No JavaScript at all</strong> — fewer bytes, no parse/compile cost</li>
</ul>
<p class="post-p">
For comparison, the traditional JavaScript approach:
</p>

<pre class="code-block"><code class="language-js">// ❌ Old way — main-thread, expensive
<p class="post-p">
window.addEventListener('scroll', () =&amp;gt; {
const progress = window.scrollY / (docHeight - winHeight);
element.style.transform = <code class="inline-code">scale(${1 - progress * 0.2})</code>;
// Runs on every scroll event — dozens per second
// Forces style recalc + layout + paint
});
</code></pre>
</p>

<p class="post-p">
The CSS way:
</p>

<pre class="code-block"><code class="language-css">/<em> ✅ New way — off-main-thread, compositor-only </em>/
<p class="post-p">
animation-timeline: scroll(root);
animation: shrink linear;
</code></pre>
</p>

<p class="post-p">
Orders of magnitude better for performance.
</p>

<h2 class="post-h2">Common Pitfalls</h2>

<h3 class="post-h3">1. Timeline scope issues</h3>

<p class="post-p">
Named timelines are scoped to the element and its descendants. You can't reference a timeline from a sibling or ancestor.
</p>

<pre class="code-block"><code class="language-css">/<em> ❌ Won't work — .other-section is a sibling of .gallery </em>/
<p class="post-p">
.gallery { scroll-timeline-name: --g; }
.other-section { animation-timeline: --g; }
</p>

<p class="post-p">
/<em> ✅ Works — descendant can access ancestor's timeline </em>/
.gallery { scroll-timeline-name: --g; }
.gallery .item { animation-timeline: --g; }
</code></pre>
</p>

<h3 class="post-h3">2. <code class="inline-code">overflow: hidden</code> kills scroll timelines</h3>

<p class="post-p">
If the scroller has <code class="inline-code">overflow: hidden</code>, there's no scroll progress — the timeline stays at 0. Use <code class="inline-code">overflow: auto</code> or <code class="inline-code">overflow: scroll</code> instead.
</p>

<h3 class="post-h3">3. <code class="inline-code">animation-fill-mode</code> with <code class="inline-code">view()</code></h3>

<p class="post-p">
When using <code class="inline-code">view()</code> timelines, the animation can jump back to its initial state when the element leaves the viewport. Use <code class="inline-code">animation-fill-mode: forwards</code> or <code class="inline-code">both</code>:
</p>

<pre class="code-block"><code class="language-css">.card {
<p class="post-p">
animation: reveal linear both;
animation-timeline: view();
}
</code></pre>
</p>

<h3 class="post-h3">4. Timeline attachment timing</h3>

<p class="post-p">
The <code class="inline-code">animation-timeline</code> property must be set on the <strong>same element</strong> as the <code class="inline-code">animation</code>. You can't attach a timeline from a parent and apply animation properties on children.
</p>

<h2 class="post-h2">Debugging Scroll-Driven Animations</h2>

<p class="post-p">
Chrome DevTools has excellent support:
</p>

<ul class="post-ul"><li class="post-li">Open DevTools → <strong>Elements</strong> panel</li>
<li class="post-li">Find an element with a scroll-driven animation</li>
<li class="post-li">Look for the <code class="inline-code">animations</code> badge next to the element</li>
<li class="post-li">Click it to open the <strong>Animations</strong> panel</li>
<li class="post-li">You'll see the scroll-driven timeline visualized as a scrollbar you can drag</li>
</ul>
<p class="post-p">
Firefox also surfaces scroll timelines in its Animations inspector.
</p>

<p class="post-p">
Navigate to <code class="inline-code">chrome://flags</code> to enable <strong>Scroll-driven Animations debugging tools</strong> for even more visualization.
