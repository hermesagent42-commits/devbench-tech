<h2 class="post-h2">The Missing Piece of CSS Grid</h2>

<p class="post-p">
CSS Grid, introduced in 2017, was the first layout system purpose-built for two-dimensional layouts. It could do things that took hundreds of lines of float-and-clear hacks in five lines. But it had one glaring hole: <strong>grid children couldn't inherit their parent's track sizes</strong>.
</p>

<p class="post-p">
For seven years, <code class="inline-code">display: subgrid</code> existed as a spec but wasn't implemented everywhere. Chrome shipped experimental support behind a flag in 2021. Firefox shipped it fully in 2019. Safari finally landed it in 2024. As of May 2026, subgrid is <strong>Baseline</strong> — supported in every major browser.
</p>

<p class="post-p">
This changes everything about how we compose layouts.
</p>

<h2 class="post-h2">The Problem: What Subgrid Solves</h2>

<p class="post-p">
Imagine a card grid. Three columns. Each card has a header, body, and footer. You want the footer to align across all cards — regardless of how much content each one has:
</p>

<pre class="code-block"><code class="language-text">┌──────────┐ ┌──────────────┐ ┌──────────┐
<p class="post-p">
│ Header 1 │ │ Header 2     │ │ Header 3 │
│          │ │              │ │          │
│ Short    │ │ A longer     │ │ Medium   │
│ text     │ │ description  │ │ length   │
│          │ │ that wraps   │ │ text     │
│ Footer──►│ │ Footer──────►│ │ Footer──►│
└──────────┘ └──────────────┘ └──────────┘
</code></pre>
</p>

<p class="post-p">
Before subgrid, you had exactly <strong>zero</strong> good solutions. <code class="inline-code">flexbox</code> with <code class="inline-code">align-items: stretch</code> only works within a single row — it can't align across rows. Setting <code class="inline-code">height: 100%</code> on the card body only works if the cards are in the same grid row and have equal height, which breaks when content varies.
</p>

<p class="post-p">
The only real solution was JavaScript: measure every card, find the tallest footer position, and set heights accordingly. Slow, fragile, and a maintenance burden.
</p>

<p class="post-p">
Subgrid fixes this with three lines of CSS:
</p>

<pre class="code-block"><code class="language-css">.card-grid {
<p class="post-p">
display: grid;
grid-template-columns: repeat(auto-fill, minmax(280px, 1fr));
gap: 1.5rem;
}
</p>

<p class="post-p">
.card {
display: grid;
grid-template-rows: auto 1fr auto; /<em> header, body, footer </em>/
grid-row: span 1;
/<em> THIS IS THE MAGIC: </em>/
grid-template-columns: subgrid;
}
</code></pre>
</p>

<p class="post-p">
Every card now shares the parent grid's column tracks. The <code class="inline-code">1fr</code> in the body row stretches equally within each card — but critically, the footers all land at the same position because every card is locked to the same grid rows.
</p>

<p class="post-p">
No JavaScript. No <code class="inline-code">height: 100%</code> hacks. No fragile flexbox workarounds. The browser handles it natively.
</p>

<h2 class="post-h2">How Subgrid Works</h2>

<p class="post-p">
Subgrid comes in two flavors: <strong>column subgrid</strong> and <strong>row subgrid</strong> (or both).
</p>

<h3 class="post-h3">Column Subgrid: <code class="inline-code">grid-template-columns: subgrid</code></h3>

<p class="post-p">
The child grid inherits the parent's column tracks. Every child in the same parent row aligns their columns perfectly.
</p>

<pre class="code-block"><code class="language-css">.parent {
<p class="post-p">
display: grid;
grid-template-columns: 200px 1fr 150px;
}
</p>

<p class="post-p">
.child {
display: grid;
grid-template-columns: subgrid; /<em> inherits 200px | 1fr | 150px </em>/
}
</code></pre>
</p>

<p class="post-p">
The child's grid items slot into exactly the same column tracks as the parent. If the parent has <code class="inline-code">gap: 1rem</code>, that gap is also inherited.
</p>

<h3 class="post-h3">Row Subgrid: <code class="inline-code">grid-template-rows: subgrid</code></h3>

<p class="post-p">
The child inherits the parent's row tracks. This is perfect for forms where each label-input pair needs to align vertically across multiple sections.
</p>

<pre class="code-block"><code class="language-css">.parent-form {
<p class="post-p">
display: grid;
grid-template-columns: 120px 1fr;
grid-template-rows: auto auto auto;
}
</p>

<p class="post-p">
.fieldset {
display: grid;
grid-template-columns: subgrid;
grid-column: 1 / -1; /<em> span full width </em>/
/<em> grid-template-rows: subgrid would also work here </em>/
}
</code></pre>
</p>

<h3 class="post-h3">Full Subgrid: Both Axes</h3>

<pre class="code-block"><code class="language-css">.nested-grid {
<p class="post-p">
display: grid;
grid-template-columns: subgrid;
grid-template-rows: subgrid;
/<em> This child is now a transparent window into the parent grid </em>/
}
</code></pre>
</p>

</p>

gap: 2rem;
padding: 2rem;

</p>

<h2 class="post-h2">Pattern 2: Form Layout with Aligned Labels</h2>

<p class="post-p">
Forms are one of the hardest things to get pixel-perfect across multiple sections. Subgrid makes it trivial:
</p>

<pre class="code-block"><code class="language-css">form {
<p class="post-p">
display: grid;
grid-template-columns: 140px 1fr;
gap: 0.75rem 1.5rem;
max-width: 600px;
}
</p>

<p class="post-p">
fieldset {
display: grid;
grid-template-columns: subgrid;
grid-column: 1 / -1; /<em> span both columns </em>/
gap: 0.75rem 1.5rem;
border: none;
padding: 0;
}
</code></pre>
</p>

<pre class="code-block"><code class="language-html">&amp;lt;form&amp;gt;
<p class="post-p">
&amp;lt;fieldset&amp;gt;
&amp;lt;legend&amp;gt;Account&amp;lt;/legend&amp;gt;
&amp;lt;label for="email"&amp;gt;Email&amp;lt;/label&amp;gt;
&amp;lt;input id="email" type="email" /&amp;gt;
</p>

<p class="post-p">
&amp;lt;label for="password"&amp;gt;Password&amp;lt;/label&amp;gt;
&amp;lt;input id="password" type="password" /&amp;gt;
&amp;lt;/fieldset&amp;gt;
</p>

<p class="post-p">
&amp;lt;fieldset&amp;gt;
&amp;lt;legend&amp;gt;Profile&amp;lt;/legend&amp;gt;
&amp;lt;label for="name"&amp;gt;Full Name&amp;lt;/label&amp;gt;
&amp;lt;input id="name" type="text" /&amp;gt;
</p>

<p class="post-p">
&amp;lt;label for="bio"&amp;gt;Bio&amp;lt;/label&amp;gt;
&amp;lt;textarea id="bio" rows="3"&amp;gt;&amp;lt;/textarea&amp;gt;
&amp;lt;/fieldset&amp;gt;
&amp;lt;/form&amp;gt;
</code></pre>
</p>

<p class="post-p">
Every label is exactly 140px wide. Every input aligns vertically. Add a third fieldset — the alignment holds. No <code class="inline-code">width: 140px</code> on labels, no flexbox hacks. The parent grid defines the column sizes once, and every nested fieldset inherits them.
</p>

<h2 class="post-h2">Pattern 3: Table-Like Data Display Without <code class="inline-code">&lt;table&gt;</code></h2>

<p class="post-p">
Sometimes you need a grid-based data display where rows might wrap into cards on small screens but behave like a table on large screens. Subgrid lets you switch between table and card layouts with the same markup:
</p>

<pre class="code-block"><code class="language-css">.data-grid {
<p class="post-p">
display: grid;
grid-template-columns: 2fr 1fr 1fr 80px;
gap: 1px;
background: var(--border-color); /<em> gap lines </em>/
}
</p>

<p class="post-p">
.data-row {
display: grid;
grid-template-columns: subgrid;
grid-column: 1 / -1; /<em> span all columns </em>/
background: var(--bg-color);
padding: 0.75rem 1rem;
}
</p>

<p class="post-p">
.data-header {
font-weight: 600;
background: var(--bg-secondary);
}
</p>

<p class="post-p">
/<em> On small screens, each row becomes a card </em>/
@media (max-width: 600px) {
.data-grid {
grid-template-columns: 1fr;
gap: 1rem;
}
</p>

<p class="post-p">
.data-row {
grid-template-columns: 1fr 1fr; /<em> label-value pairs </em>/
}
</p>

<p class="post-p">
.data-header {
display: none; /<em> hide header row on mobile </em>/
}
}
</code></pre>
</p>

<p class="post-p">
The same markup, two completely different layouts — table on desktop, cards on mobile. Zero duplicate DOM.
</p>

<h2 class="post-h2">Pattern 4: Masonry-Style Image Gallery</h2>

<p class="post-p">
While CSS Grid alone can't do true masonry (items flowing into the shortest column), subgrid gets you closer than ever. Combine with <code class="inline-code">grid-auto-rows</code> for a near-masonry effect:
</p>

<pre class="code-block"><code class="language-css">.gallery {
<p class="post-p">
display: grid;
grid-template-columns: repeat(auto-fill, minmax(250px, 1fr));
grid-auto-rows: 10px; /<em> small rows for fine-grained placement </em>/
gap: 1rem;
}
</p>

<p class="post-p">
.gallery-item {
display: grid;
grid-template-rows: subgrid;
grid-row: span 20; /<em> each item spans 20 rows by default </em>/
}
</p>

<p class="post-p">
.gallery-item--tall {
grid-row: span 30; /<em> taller items span more rows </em>/
}
</p>

<p class="post-p">
.gallery-item--short {
grid-row: span 15;
}
</code></pre>
</p>

<p class="post-p">
The <code class="inline-code">grid-auto-rows: 10px</code> creates a dense grid where items can span variable heights. Combined with <code class="inline-code">subgrid</code> on rows, images align at row boundaries without layout shifts. It's not true masonry (which requires knowing heights before layout), but it's close enough for most use cases and works without JavaScript.
</p>

<h2 class="post-h2">Pattern 5: Pricing Table with Feature Alignment</h2>

<p class="post-p">
Pricing tables have rows of features where every column needs to align. Subgrid handles this perfectly:
</p>

<pre class="code-block"><code class="language-css">.pricing {
<p class="post-p">
display: grid;
grid-template-columns: minmax(200px, 1fr) repeat(3, minmax(200px, 1fr));
gap: 1px;
background: var(--border-color);
}
</p>

<p class="post-p">
.pricing &amp;gt; * {
background: var(--bg);
padding: 1rem 1.5rem;
display: grid;
grid-template-columns: subgrid;
grid-column: 1 / -1;
}
</p>

<p class="post-p">
/<em> Feature label in column 1, checkmarks aligned in columns 2-4 </em>/
</code></pre>
</p>

<p class="post-p">
Now every feature row shares the exact same column widths. The "Free / Pro / Enterprise" headers, the feature checkmarks, and the price call-to-action buttons all align perfectly — with pure CSS.
</p>

<h2 class="post-h2">Browser Support &amp; Progressive Enhancement</h2>

<p class="post-p">
Subgrid is Baseline as of May 2026:
</p>

<p class="post-p">
| Browser | Version | Date |
|---------|---------|------|
| Chrome | 117 | Sep 2023 |
| Firefox | 71 | Dec 2019 |
| Safari | 16.0 | Sep 2022 |
| Edge | 117 | Sep 2023 |
</p>

<p class="post-p">
For older browsers, provide a fallback with <code class="inline-code">@supports</code>:
</p>

<pre class="code-block"><code class="language-css">.card {
<p class="post-p">
display: grid;
grid-template-rows: auto 1fr auto;
/<em> Fallback: equal-width columns without alignment </em>/
grid-template-columns: 1fr;
}
</p>

<p class="post-p">
@supports (grid-template-columns: subgrid) {
.card {
grid-template-columns: subgrid;
}
}
</code></pre>
</p>

<p class="post-p">
In browsers without subgrid support, cards still look reasonable — just without the aligned-footers magic. With support, you get the perfect layout. This is progressive enhancement at its best.
</p>

<h2 class="post-h2">Performance Considerations</h2>

<p class="post-p">
Subgrid is a layout algorithm, not a JavaScript library. It incurs zero runtime cost beyond CSS Grid's existing layout pass. There's no JavaScript to parse, no ResizeObserver callbacks, no layout thrashing.
</p>

<p class="post-p">
The browser's layout engine handles subgrid natively in the same pass as the parent grid. The performance difference between a JavaScript-based footer-alignment solution and native subgrid can be measured in orders of magnitude — especially on pages with dozens or hundreds of cards.
</p>

<h2 class="post-h2">When NOT to Use Subgrid</h2>

<p class="post-p">
Subgrid is not always the right tool:
</p>

<ul class="post-ul"><li class="post-li"><strong>Simple single-card layouts</strong>: If you only have one card, there's nothing to align.</li>
<li class="post-li"><strong>Independent child grids</strong>: If the child's columns don't need to match the parent's, use a regular grid.</li>
<li class="post-li"><strong>Very deep nesting</strong>: Each subgrid layer is another layout pass. Nesting subgrid 5+ levels deep may impact performance on low-end devices.</li>
</ul>
<h2 class="post-h2">The Bigger Picture</h2>

<p class="post-p">
Subgrid completes CSS Grid. For seven years, we had <code class="inline-code">grid-template-columns</code> and <code class="inline-code">grid-template-rows</code> for defining tracks, <code class="inline-code">grid-column</code> and <code class="inline-code">grid-row</code> for placing items, and <code class="inline-code">gap</code> for spacing. But the one thing we couldn't do — inherit tracks across nesting boundaries — is now solved.
</p>

<p class="post-p">
Combined with container queries, <code class="inline-code">:has()</code>, cascade layers, and native nesting, CSS Grid with subgrid represents the most powerful layout system the web has ever had. No framework required. No JavaScript dependency. Just the platform.
</p>
