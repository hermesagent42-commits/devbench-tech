CSS Gap Decorations: Styling the Space Between

Chrome 149 shipped column-rule and row-rule for grid and flexbox gaps. No more extra DOM elements or pseudo-element hacks to draw lines between items.

June 10, 20268 minby DevBench Team
CSSGap DecorationsGridFlexboxcolumn-rulerow-ruleChrome 149

On June 2, 2026, Chrome 149 shipped with a feature that frontend developers have been requesting for over a decade: CSS Gap Decorations. The idea is simple but powerful — you can now style the gaps between items in grid and flexbox layouts with column-rule and row-rule, exactly like you style column gaps in multi-column layout.

This eliminates one of the most common CSS workarounds: adding empty divs, using ::before/::after pseudo-elements, or painting backgrounds to simulate dividers between layout items. Let's dive into what makes this feature so important and how to use it.

The Problem: Gap Styling Before June 2026

CSS Grid and Flexbox introduced the gap property — the ability to create space between items without margin hacks. This was a massive improvement for layout code. But there was a catch: you couldn't style the gap. You couldn't draw a line, a dash, or any visual decoration in that space.

Developers relied on several workarounds, each with significant downsides:

WorkaroundDownside
Empty divs between itemsPollutes DOM, breaks semantic HTML, complicates responsive layout
::before/::after pseudo-elementsLimited to two pseudo-elements per element, positioning is fragile
Background on container + gaps show throughOnly works for simple solid backgrounds, not patterns or borders
Border on items (half-border trick)Creates doubled borders at edges, requires :first-child/:last-child overrides
Outline + negative marginOutline doesn't follow border-radius, looks wrong with rounded corners

Every single one of these approaches is a hack. They all add complexity, hurt maintainability, and break in edge cases. Gap decorations solve this at the platform level.

The Solution: column-rule and row-rule

CSS Gap Decorations introduce two new properties that work alongside gap:

  • column-rule — Styles the vertical gaps between columns in a grid or flex layout
  • row-rule — Styles the horizontal gaps between rows in a grid or flex layout

The syntax mirrors the familiar column-rule from multi-column layout (which has existed since CSS3). It's a shorthand for column-rule-width, column-rule-style, and column-rule-color:

/* Grid with styled gaps */
.grid {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 20px;
  column-rule: 2px solid #6366f1;
  row-rule: 1px dashed #94a3b8;
}

/* Flexbox with vertical dividers */
.flex-row {
  display: flex;
  gap: 16px;
  column-rule: 1px dotted #cbd5e1;
}

Firefox and Safari are actively working on support through the Interop 2026 program. For production use, combine with @supports for graceful fallbacks:

@supports (column-rule: 1px solid red) {
  .grid {
    column-rule: 2px solid var(--border-color);
  }
}

@supports not (column-rule: 1px solid red) {
  /* Fallback: use border on items with :not(:last-child) */
  .grid > *:not(:last-child) {
    border-right: 1px solid var(--border-color);
  }
}

Real-World Use Cases

1. Dashboard Cards with Divider Lines

Before gap decorations, adding vertical dividers between dashboard cards required either extra divs or careful border management:

.dashboard-grid {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 24px;
  column-rule: 1px solid #e2e8f0;
}

Clean. One line. No DOM pollution.

2. Photo Gallery Grid

Photo galleries often want subtle separators between images. Border on images creates problems — the border becomes part of the image box, throwing off aspect ratios and requiring box-sizing adjustments:

.gallery {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(200px, 1fr));
  gap: 4px;
  column-rule: 2px solid #0f172a;
  row-rule: 2px solid #0f172a;
  background: #0f172a; /* Gaps show the background */
}

3. Flexbox Navigation with Separators

Horizontal nav bars with pipe separators between items have always been awkward. Now:

nav {
  display: flex;
  gap: 0;
  column-rule: 1px solid #64748b;
}

nav a {
  padding: 8px 16px;
}

4. Form Layout Grid

Two-column forms with a visual divider between label and input columns:

.form-grid {
  display: grid;
  grid-template-columns: 200px 1fr;
  gap: 16px;
  column-rule: 1px solid #e2e8f0;
}

Comparison: Before and After

Let's look at a concrete example. Here's a 3-column feature grid with styled dividers — the old way and the new way:

/* OLD WAY: Border hacks */
.features {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 0; /* Can't use gap — need borders to touch */
}
.features > * {
  padding: 32px;
  border-right: 1px solid #e2e8f0;
  border-bottom: 1px solid #e2e8f0;
}
.features > *:nth-child(3n) {
  border-right: none; /* Remove right border on last column */
}
.features > *:nth-child(n+4) {
  border-bottom: none; /* Remove bottom border on last row */
}

/* NEW WAY: Gap decorations */
.features {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 0;
  column-rule: 1px solid #e2e8f0;
  row-rule: 1px solid #e2e8f0;
}
.features > * {
  padding: 32px;
}

The new approach is 60% less CSS and doesn't require child selectors that break when items wrap or reorder. It also works correctly regardless of how many items are in the grid — unlike nth-child hacks that need updating when the column count changes.

Performance Considerations

Gap decorations are rendered by the layout engine, not the paint engine. This means:

  • No additional paint layers or composite layers
  • No impact on layout thrashing
  • Hardware-accelerated where the browser supports it
  • Zero JavaScript overhead — no ResizeObserver, no scrollHeight calculations

Compared to the pseudo-element approach (which creates additional boxes in the layout tree), gap decorations are significantly more performant.

Limitations and Gotchas

  • No gap decorations for single items. If a grid or flex container has only one item, there's no gap to decorate — rules won't render.
  • Gap must be non-zero. With gap: 0, rules render in zero-width space (invisible). Use gap: 1px or larger.
  • No border-radius on rules. Rules are straight lines. For curved dividers, you still need other approaches.
  • Rules span the full row/column extent. You can't make a rule shorter than the gap it occupies.
  • Flexbox wrap interaction. In a wrapped flex container, column-rule only applies within each row. There's no cross-row column rule.

The Bigger Picture: CSS in 2026

Gap decorations are part of a broader wave of CSS improvements landing in 2026. Alongside CSS Mixins, reading-flow, cross-document view transitions, and scroll-state container queries, the platform is filling gaps (pun intended) that previously required JavaScript or complex CSS hacks.

The trend is clear: if developers have been hacking around a missing feature for years, the CSS Working Group is working on a native solution. The days of border tricks, pseudo-element positioning, and empty divs are numbered.
