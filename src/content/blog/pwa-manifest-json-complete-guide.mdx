## What manifest.json Actually Does

A web app manifest is a JSON file that tells the browser how your application should behave when installed on a device. It controls the name, icons, theme color, display mode, splash screen, and how your app appears in the app launcher.

In 2026, PWAs are installable on every major platform — Windows, macOS, Linux, Android, iOS, iPadOS, and ChromeOS. A well-crafted manifest is the difference between your app feeling like a native application and feeling like a weird bookmark.

## The Minimum Viable Manifest

Here's the absolute minimum you need for an installable PWA:

```json
{
  "name": "My App",
  "short_name": "App",
  "start_url": "/",
  "display": "standalone",
  "icons": [
    {
      "src": "/icon-192.png",
      "sizes": "192x192",
      "type": "image/png"
    },
    {
      "src": "/icon-512.png",
      "sizes": "512x512",
      "type": "image/png"
    }
  ]
}
```

Link it in your HTML:

```html
<link rel="manifest" href="/manifest.json" />
```

Without at least a 192×192 and 512×512 icon, Chrome won't show the install prompt. Without `display: standalone`, your app opens in a browser tab. Without `start_url`, you get redirected to the wrong page on launch.

## Every Field, Explained

### Identity

- **`name`** (required): The full app name. Used in the app launcher title, install prompt, and splash screen. Keep it under 45 characters for best display.
- **`short_name`** (required): A 12-character max shorthand. Used on the home screen below the icon when space is tight.
- **`description`**: A short description of your app. Android uses this in the app info screen.
- **`lang`**: The primary language of `name` and `short_name`. Helps with accessibility and text rendering.
- **`dir`**: Text direction: `ltr`, `rtl`, or `auto`. Use with `lang` for right-to-left languages.

### Display

- **`display`** (required): How the app appears when launched:
  - `standalone` — looks like a native app (no browser chrome). **This is what you want.**
  - `fullscreen` — no status bar, no navigation. Only for games and immersive experiences.
  - `minimal-ui` — minimal browser controls. Similar to standalone on most platforms.
  - `browser` — opens in a regular browser tab. Don't use this for PWAs.

- **`display_override`**: A priority list of display modes. If the browser supports `window-controls-overlay`, it'll use that. Otherwise falls back through the list.

```json
"display_override": ["window-controls-overlay", "standalone", "minimal-ui"]
```

- **`orientation`**: Lock the screen orientation: `portrait`, `landscape`, `any`, `natural`, `portrait-primary`, etc.

### Theme & Appearance

- **`theme_color`**: The toolbar and status bar color. Sets the "brand" color of your PWA's window. Use your brand's primary color.
- **`background_color`**: The splash screen background. Shows while the app loads. Should match your app's body background to avoid a flash.
- **`scope`**: Limits which URLs the app can navigate to while staying in standalone mode. Defaults to the `start_url` directory.

### Icons (Critical)

Icons are the most common failure point. Here's a production-quality icon set:

```json
"icons": [
  { "src": "/icons/icon-48.png", "sizes": "48x48", "type": "image/png" },
  { "src": "/icons/icon-72.png", "sizes": "72x72", "type": "image/png" },
  { "src": "/icons/icon-96.png", "sizes": "96x96", "type": "image/png" },
  { "src": "/icons/icon-144.png", "sizes": "144x144", "type": "image/png" },
  { "src": "/icons/icon-192.png", "sizes": "192x192", "type": "image/png" },
  { "src": "/icons/icon-512.png", "sizes": "512x512", "type": "image/png" },
  { "src": "/icons/icon-192-maskable.png", "sizes": "192x192", "type": "image/png", "purpose": "maskable" },
  { "src": "/icons/icon-512-maskable.png", "sizes": "512x512", "type": "image/png", "purpose": "maskable" }
]
```

Key points:
- **Always include 192×192 and 512×512** — these are required for Chrome's install prompt.
- **Always include maskable icons** — Android applies adaptive icon masking (circles, squircles, rounded squares). Without `purpose: "maskable"`, your icon gets a white background behind the mask and looks broken.
- **Safe zone for maskable**: Keep your icon content within the center 80% of the canvas. The outer 20% may be clipped.
- **Use PNG**: Every platform supports it. SVG is technically allowed but poorly supported across platforms.
- **Include monochrome**: `"purpose": "monochrome"` icons for notification trays and system UI.

### Shortcuts

App shortcuts let users jump directly to common actions from the app icon (right-click on desktop, long-press on mobile):

```json
"shortcuts": [
  {
    "name": "New Note",
    "short_name": "Note",
    "description": "Create a new note",
    "url": "/notes/new",
    "icons": [{ "src": "/icons/new-note.png", "sizes": "96x96" }]
  },
  {
    "name": "Search",
    "short_name": "Search",
    "description": "Search your notes",
    "url": "/search",
    "icons": [{ "src": "/icons/search.png", "sizes": "96x96" }]
  }
]
```

### Screenshots

Screenshots appear in install dialogs and app stores (Microsoft Store, Google Play Trusted Web Activity):

```json
"screenshots": [
  {
    "src": "/screenshots/home-desktop.png",
    "sizes": "1280x720",
    "type": "image/png",
    "form_factor": "wide",
    "label": "Dashboard view on desktop"
  },
  {
    "src": "/screenshots/home-mobile.png",
    "sizes": "750x1334",
    "type": "image/png",
    "form_factor": "narrow",
    "label": "Dashboard on mobile"
  }
]
```

### Categories

Helps app stores and search categorize your PWA:

```json
"categories": ["productivity", "utilities"]
```

Valid categories: `books`, `business`, `education`, `entertainment`, `finance`, `fitness`, `food`, `games`, `health`, `kids`, `lifestyle`, `music`, `navigation`, `news`, `personalization`, `photo`, `productivity`, `reference`, `shopping`, `social`, `sports`, `travel`, `utilities`, `weather`.

### Protocol Handlers

Register your PWA to handle custom URL schemes:

```json
"protocol_handlers": [
  {
    "protocol": "web+notes",
    "url": "/open?note=%s"
  }
]
```

Now `web+notes:123` URLs open your PWA. The `%s` placeholder receives the URI content after the colon. This works with `mailto`, `web+*`, and more.

### File Handlers

Let your PWA register as a file handler — users can "Open with" your app from the file manager:

```json
"file_handlers": [
  {
    "action": "/open-file",
    "accept": {
      "text/plain": [".txt", ".md"],
      "application/json": [".json"]
    }
  }
]
```

### Related Applications

Tell the platform about your native app counterparts:

```json
"related_applications": [
  {
    "platform": "play",
    "url": "https://play.google.com/store/apps/details?id=com.example.app",
    "id": "com.example.app"
  }
],
"prefer_related_applications": false
```

When `prefer_related_applications` is `true`, the platform skips the PWA install prompt and directs users to the native app store instead. Keep it `false` unless you're intentionally pushing users away from the PWA.

## Platform-Specific Requirements

### iOS / iPadOS

Apple doesn't read `manifest.json` directly. You also need:

```html
<!-- iOS meta tags -->
<meta name="apple-mobile-web-app-capable" content="yes" />
<meta name="apple-mobile-web-app-status-bar-style" content="black-translucent" />
<meta name="apple-mobile-web-app-title" content="My App" />

<!-- iOS splash screens -->
<link rel="apple-touch-startup-image" href="/splash/apple-splash-2048-2732.png"
      media="(device-width: 1024px) and (device-height: 1366px)" />

<!-- iOS icons -->
<link rel="apple-touch-icon" href="/icons/icon-180.png" sizes="180x180" />
```

Safari 17+ reads `manifest.json` for the name, theme color, and display mode, but icons and splash screens still need `apple-touch-icon` and `apple-touch-startup-image`.

### Windows

Windows uses the manifest plus optional metadata for the Microsoft Store:

- Set `display_override: ["window-controls-overlay"]` for native-feeling title bar customization
- Use the `edge_side_panel` member for sidebar integration
- The `screenshots` array and `description` feed the Microsoft Store listing

### Android / Trusted Web Activity

For Google Play distribution via TWA, the manifest must match your Play Store listing (name, icons, screenshots). Use `prefer_related_applications: false` so the PWA promotes itself rather than redirecting to the Play Store.

## Validation Checklist

Before shipping, verify:

- [ ] `name` and `short_name` are set and different
- [ ] `display` is `standalone` (not `browser`)
- [ ] At least one 192×192 and 512×512 icon
- [ ] Maskable icons with `purpose: "maskable"` and proper safe zones
- [ ] `theme_color` matches your brand color
- [ ] `background_color` matches your page background
- [ ] `start_url` is `"/"` or the correct entry point
- [ ] `scope` doesn't restrict navigation unexpectedly
- [ ] Screenshots are 1280×720 (desktop) and ~750×1334 (mobile) PNGs
- [ ] Categories match your app's purpose

## Testing Your Manifest

Open Chrome DevTools → Application → Manifest. You'll see every field parsed, icon previews, and any warnings. Chrome will flag missing maskable icons, undersized icons, and mismatched theme/background colors.

For real install testing: serve over HTTPS on a real device. The install prompt won't appear on `localhost` unless you bypass engagement checks in `chrome://flags`.

Here's a complete manifest you can adapt:

```json
{
  "name": "MyApp",
  "short_name": "MyApp",
  "description": "A description of MyApp for app stores and search results.",
  "lang": "en",
  "start_url": "/",
  "display": "standalone",
  "display_override": ["window-controls-overlay", "standalone"],
  "theme_color": "#0f172a",
  "background_color": "#0f172a",
  "scope": "/",
  "orientation": "any",
  "categories": ["productivity"],
  "icons": [
    { "src": "/icons/icon-192.png", "sizes": "192x192", "type": "image/png" },
    { "src": "/icons/icon-512.png", "sizes": "512x512", "type": "image/png" },
    { "src": "/icons/icon-192-maskable.png", "sizes": "192x192", "type": "image/png", "purpose": "maskable" },
    { "src": "/icons/icon-512-maskable.png", "sizes": "512x512", "type": "image/png", "purpose": "maskable" }
  ],
  "screenshots": [
    { "src": "/screenshots/desktop.png", "sizes": "1280x720", "type": "image/png", "form_factor": "wide" },
    { "src": "/screenshots/mobile.png", "sizes": "750x1334", "type": "image/png", "form_factor": "narrow" }
  ],
  "shortcuts": [
    { "name": "Dashboard", "url": "/dashboard", "icons": [{ "src": "/icons/dashboard.png", "sizes": "96x96" }] }
  ]
}
```

PWAs are no longer experimental or "good enough." With a complete manifest, they're indistinguishable from native apps — and they ship with zero app store review process.
