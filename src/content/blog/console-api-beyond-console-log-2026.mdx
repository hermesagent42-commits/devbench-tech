`console.log()` is the most-used JavaScript debugging tool on the planet. Open any developer's browser console, and you'll see walls of `console.log('here')`, `console.log(data)`, `console.log('wtf', x)`. It's the first debugging method we learn, and for many, the only one they ever use.

But the Console API has **20+ methods** that replace entire debugging workflows. Some have been in browsers for over a decade. Most developers don't know they exist.

This guide covers every `console.*` method worth knowing in 2026 -- with practical use cases, browser compatibility, and production patterns you'll actually use.

## `console.table()`: The Data Inspector

Stop logging arrays and objects with `console.log()`. `console.table()` renders them as interactive sortable tables in DevTools.

```js
const users = [
  { id: 1, name: 'Alice', role: 'admin', active: true },
  { id: 2, name: 'Bob', role: 'editor', active: false },
  { id: 3, name: 'Carol', role: 'viewer', active: true },
];

console.table(users);
// Sortable table with columns: id, name, role, active
```

**Select specific columns:**

```js
console.table(users, ['name', 'role']);
// Only shows name and role columns
```

This is transformative for debugging API responses, database queries, and any structured data. You can click column headers to sort ascending/descending. Chrome also lets you copy the table as CSV via right-click.

**When to use:** Every time you're debugging an array of objects. Replace `console.log(JSON.stringify(data, null, 2))` with `console.table(data)`.

## `console.group()` / `console.groupCollapsed()`: Structured Logging

When you have nested logic -- a function that calls other functions -- flat logs become unreadable. `console.group()` creates collapsible sections:

```js
function processOrder(order) {
  console.group(`Order #${order.id}`);
  console.log('Status:', order.status);
  console.log('Items:', order.items.length);

  console.group('Line Items');
  order.items.forEach((item, i) => {
    console.groupCollapsed(`Item ${i + 1}: ${item.name}`);
    console.log('SKU:', item.sku);
    console.log('Price:', item.price);
    console.log('Quantity:', item.qty);
    console.groupEnd();
  });
  console.groupEnd();

  console.groupEnd();
}

processOrder({
  id: 'ORD-4829',
  status: 'processing',
  items: [
    { name: 'Widget', sku: 'W-100', price: 9.99, qty: 2 },
    { name: 'Gadget', sku: 'G-200', price: 24.99, qty: 1 },
  ],
});
```

In Chrome DevTools, this renders as a nested tree you can expand and collapse -- like a file browser. `groupCollapsed()` starts closed, perfect for details you inspect on demand.

**When to use:** Any multi-step function with sub-operations. Log the high-level steps as groups and nest details inside. Combined with `console.table()` inside groups, it's a complete inspection workflow.

## `console.time()` / `console.timeEnd()`: Performance Profiling Without Performance API

`console.time()` gives you high-precision elapsed time -- no need for `Date.now()` math or `performance.now()` tracking:

```js
console.time('fetchUsers');
const users = await fetch('/api/users').then(r => r.json());
console.timeEnd('fetchUsers');
// -> fetchUsers: 234.5ms

console.time('renderTable');
renderUserTable(users);
console.timeEnd('renderTable');
// -> renderTable: 12.3ms
```

**Named timers can be nested and interleaved:**

```js
console.time('total');

console.time('step-parse');
const parsed = parseData(raw);
console.timeEnd('step-parse');

console.time('step-validate');
const valid = validate(parsed);
console.timeEnd('step-validate');

console.time('step-render');
render(valid);
console.timeEnd('step-render');

console.timeEnd('total');
// -> step-parse: 2.1ms
// -> step-validate: 0.3ms
// -> step-render: 15.7ms
// -> total: 18.4ms
```

**`console.timeLog()` reports intermediate times:**

```js
console.time('loop');
for (let i = 0; i < 1000000; i++) {
  if (i % 250000 === 0) console.timeLog('loop', `Iteration ${i}`);
}
console.timeEnd('loop');
// -> loop: 0.2ms Iteration 0
// -> loop: 15.3ms Iteration 250000
// -> loop: 30.1ms Iteration 500000
// -> loop: 44.8ms Iteration 750000
// -> loop: 59.2ms
```

**When to use:** Whenever you write `const start = Date.now();` or `performance.now()`. Named timers are self-documenting and the DevTools timeline will show them.

## `console.assert()`: Conditional Logging Without `if` Blocks

`console.assert()` only logs when its first argument is falsy:

```js
// Instead of:
if (response.status !== 200) {
  console.error('Status:', response.status, 'Body:', await response.text());
}

// Write:
console.assert(response.status === 200, 'Status:', response.status, await response.text());
// Only logs when the assertion fails (status !== 200)
```

**When to use:** Invariant checks, validation guardrails, sanity checks. Sprinkle `console.assert()` calls in critical paths and they stay silent when everything works. Much cleaner than wrapping every debug statement in an `if`.

## `console.trace()`: Stack Traces On Demand

When you need to know _who called this function_ -- not just the function itself:

```js
function validateUser(user) {
  if (!user.email) {
    console.trace('validateUser called with missing email');
    return false;
  }
  return true;
}
```

In Chrome DevTools, this outputs the full call stack with source links you can click to jump directly to the calling code. Way faster than setting a breakpoint and inspecting manually.

**When to use:** Debugging unexpected function calls, tracking down "why is this being called twice?", and confirming call paths in complex event-driven code.

## `console.count()` / `console.countReset()`: Frequency Tracking

How many times does a function actually run? Instead of counting manually:

```js
function handleClick(e) {
  console.count('Button clicks');
  // ... handler logic
}

// After 3 clicks:
// -> Button clicks: 1
// -> Button clicks: 2
// -> Button clicks: 3
```

**With labels for different entry points:**

```js
function fetchUser(id) {
  console.count(`fetchUser(${id})`);
}

function fetchAllUsers() {
  console.count('fetchAllUsers');
}

console.countReset('Button clicks'); // Reset a counter
```

**When to use:** Tracking how often an event fires, confirming memoization works, detecting unintended re-renders in React, and verifying debounce/throttle behavior.

## `console.dir()`: Inspect DOM Elements as JavaScript Objects

`console.log(document.body)` shows the HTML tree. `console.dir(document.body)` shows the JavaScript object with all properties:

```js
const el = document.querySelector('.my-component');

console.log(el);
// -> <div class="my-component">...</div>  (HTML rendering)

console.dir(el);
// -> HTMLDivElement {
//     accessKey: "",
//     align: "",
//     ariaAtomic: null,
//     ariaAutoComplete: null,
//     ... every property
//   }
```

**When to use:** Inspecting DOM element properties, checking prototype chains, exploring event listener attachments, and understanding what methods are available on an object.

## Styled Console Output with `%c`

You can style console output with CSS using the `%c` format specifier:

```js
console.log(
  '%cDeploy Successful %cv2.4.1',
  'color: #22c55e; font-size: 18px; font-weight: bold;',
  'color: #94a3b8; font-size: 12px;'
);

console.log(
  '%cWarning%c: API response time exceeded 2000ms threshold',
  'background: #f59e0b; color: #000; padding: 2px 6px; border-radius: 4px; font-weight: bold;',
  'color: #f59e0b;'
);
```

Supported CSS properties: `color`, `background`, `background-color`, `font-size`, `font-weight`, `font-style`, `font-family`, `padding`, `margin`, `border`, `border-radius`, `text-decoration`, `text-shadow`, `line-height`.

## `console.warn()` and `console.error()`: Semantic Logging Levels

These aren't just colored versions of `console.log()`. They have real behavioral differences:

- **`console.warn()`** -- Yellow output. In Node.js, writes to `stderr`. Chrome DevTools can break on warnings.
- **`console.error()`** -- Red output with stack trace in most browsers. Writes to `stderr`. Chrome can break on errors.
- **`console.debug()`** -- Same as `console.log()` but hidden by default in Chrome (enable "Verbose" level to see).

Use them semantically:

```js
// Bad - everything is log
console.log('User not found');
console.log('API timeout after 5s');
console.log('Deprecated: use /v2 endpoint');

// Good - semantic levels
console.warn('Deprecated: use /v2 endpoint instead of /v1');
console.error('API timeout after 5s - request aborted');
console.debug('Cache hit for user profile: 0.2ms');
```

## `console.clear()`: Reset Without Closing DevTools

`console.clear()` wipes the console -- useful at the start of a debug session or before a long-running operation:

```js
console.clear();
console.log('%cSession started - monitoring events...', 'font-weight: bold;');
```

Chrome preserves the "Console was cleared" message. You can also press Ctrl+L (Cmd+K on Mac) as a keyboard shortcut.

## `console.context()` (Chrome 127+, 2026): Scoped Log Filtering

The newest addition. `console.context()` creates a scoped logging namespace that you can filter independently in DevTools:

```js
const userCtx = console.context('user-service');
const authCtx = console.context('auth-service');

userCtx.log('Fetching user profile...');
userCtx.log('Profile loaded in 234ms');
authCtx.log('Token validation passed');

// In DevTools, you can now filter by context name to only see,
// for example, all 'auth-service' logs.
```

This is the solution to "my console is drowning in logs from 12 different services." Each context gets its own filter group in the new Console sidebar (Chrome 127+).

## Format Specifiers Reference

Beyond `%c` for CSS styling, `console.log()` supports several format specifiers:

| Specifier | Description | Example |
|-----------|-------------|---------|
| `%s` | String | `console.log('User: %s', name)` |
| `%d` / `%i` | Integer | `console.log('Count: %d', count)` |
| `%f` | Float | `console.log('Price: %f', 9.99)` |
| `%o` | DOM element as expandable object | `console.log('%o', document.body)` |
| `%O` | Generic object with expandable properties | `console.log('%O', complexObject)` |
| `%c` | CSS styling | `console.log('%cStyled', 'color: red')` |

## Production Logging Pattern: Structured, Toggleable, Context-Aware

Here's a production logging utility that combines everything:

```js
const Logger = {
  enabled: process.env.NODE_ENV === 'development',
  contexts: new Map(),

  context(name) {
    return {
      log: (...args) => Logger.log(`[${name}]`, ...args),
      warn: (...args) => Logger.warn(`[${name}]`, ...args),
      error: (...args) => Logger.error(`[${name}]`, ...args),
      time: (label) => Logger.time(`${name}:${label}`),
      timeEnd: (label) => Logger.timeEnd(`${name}:${label}`),
      table: (data, cols) => Logger.table(data, cols),
      group: (label, fn) => {
        console.group(`[${name}] ${label}`);
        fn();
        console.groupEnd();
      },
    };
  },

  log(...args) { if (this.enabled) console.log(...args); },
  warn(...args) { if (this.enabled) console.warn(...args); },
  error(...args) { console.error(...args); }, // Always log errors
  time(label) { if (this.enabled) console.time(label); },
  timeEnd(label) { if (this.enabled) console.timeEnd(label); },
  table(data, cols) { if (this.enabled) console.table(data, cols); },
  trace(...args) { if (this.enabled) console.trace(...args); },
  count(label) { if (this.enabled) console.count(label); },
  assert(cond, ...args) { if (this.enabled) console.assert(cond, ...args); },
};

// Usage
const apiLog = Logger.context('API');
apiLog.time('getUsers');
const users = await fetchUsers();
apiLog.timeEnd('getUsers');
apiLog.table(users, ['id', 'name', 'email']);
```

## When NOT to Use Each Method

- **`console.log()` in production**: Strip them out. They slow down the main thread, leak data, and clutter the console for power users. Use a compile-time transform or conditional wrapper.
- **`console.table()` on huge arrays**: Table rendering has overhead. For arrays >1000 items, fall back to `console.log()` or sample the data.
- **`console.trace()` in hot paths**: Stack capture is expensive. Only use it in error/assertion paths, not inside tight loops.
- **`%c` in Node.js**: Doesn't work. Use `chalk` or `kleur` instead for terminal colors.
- **`console.group()` without `groupEnd()`**: You'll mess up the nesting. Always pair them.
