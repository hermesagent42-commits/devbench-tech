<h1 class="post-h1">CSS <code class="inline-code">color-mix()</code>: The Complete Practical Guide</h1>

<p class="post-p">
CSS <code class="inline-code">color-mix()</code> landed as <strong>Baseline in April 2024</strong> and is now supported in every modern browser. It lets you mix two colors directly in CSS — no Sass, no PostCSS, no JavaScript. If you're building design systems, dark mode, or component libraries, this function will fundamentally change how you work with color.
</p>

<h2 class="post-h2">The Basics</h2>

<p class="post-p">
The syntax is straightforward:
</p>

<pre class="code-block"><code class="language-css">color-mix(in &amp;lt;color-space&amp;gt;, &amp;lt;color-1&amp;gt;, &amp;lt;color-2&amp;gt;)
<p class="post-p">
</code></pre>
</p>

<p class="post-p">
The simplest possible usage — mix red and blue equally in sRGB:
</p>

<pre class="code-block"><code class="language-css">background: color-mix(in srgb, red, blue);
<p class="post-p">
/<em> Result: rgb(128, 0, 128) — a perfect purple </em>/
</code></pre>
</p>

<p class="post-p">
By default, each color contributes 50%. You can control the proportions with percentages:
</p>

<pre class="code-block"><code class="language-css">/<em> 70% red, 30% blue </em>/
<p class="post-p">
background: color-mix(in srgb, red 70%, blue 30%);
</p>

<p class="post-p">
/<em> Only need to specify one — the other fills to 100% </em>/
background: color-mix(in srgb, red 80%, blue);
</code></pre>
</p>

<p class="post-p">
If percentages don't sum to 100%, both are scaled proportionally:
</p>

<pre class="code-block"><code class="language-css">/<em> 25% / 50% → scaled to 33.3% / 66.7% </em>/
<p class="post-p">
background: color-mix(in srgb, red 25%, blue 50%);
</code></pre>
</p>

<h2 class="post-h2">Color Spaces Matter</h2>

<p class="post-p">
The <code class="inline-code">in &lt;color-space&gt;</code> part is where <code class="inline-code">color-mix()</code> gets powerful. Different color spaces produce <strong>different intermediate colors</strong>:
</p>

<h3 class="post-h3">sRGB (default, but not the best)</h3>

<pre class="code-block"><code class="language-css">/<em> sRGB mixing — can produce muddy midpoints </em>/
<p class="post-p">
background: color-mix(in srgb, #ff0000, #0000ff);
</code></pre>
</p>

<p class="post-p">
sRGB is the web's native space but its gamma curve creates non-uniform mixing. Midpoints between complementary colors often look desaturated and dull.
</p>

<h3 class="post-h3">OKLCH — The Perceptual Powerhouse</h3>

<pre class="code-block"><code class="language-css">/<em> OKLCH — perceptually uniform, vibrant midpoints </em>/
<p class="post-p">
background: color-mix(in oklch, #ff0000, #0000ff);
</code></pre>
</p>

<p class="post-p">
OKLCH produces <strong>smoother, more natural blends</strong> because it's perceptually uniform. Equal steps in OKLCH look like equal visual changes to the human eye. This is the recommended space for most use cases.
</p>

<h3 class="post-h3">Other Color Spaces</h3>

<ul class="post-ul"><li class="post-li"><strong><code class="inline-code">in hsl</code></strong> — works like HSL color pickers, good for saturation/lightness tweaking</li>
<li class="post-li"><strong><code class="inline-code">in oklab</code></strong> — similar to OKLCH, perceptually uniform</li>
<li class="post-li"><strong><code class="inline-code">in lch</code></strong> — cylindrical OKLab, useful for hue-based mixing</li>
<li class="post-li"><strong><code class="inline-code">in display-p3</code></strong> — wide-gamut mixing for HDR displays</li>
<li class="post-li"><strong><code class="inline-code">in xyz-d65</code></strong> — the reference space, rarely needed directly</li>
</ul>
<pre class="code-block"><code class="language-css">/<em> HSL mixing — keeps saturation alive in the middle </em>/
<p class="post-p">
background: color-mix(in hsl, #ff0000, #0000ff);
</p>

<p class="post-p">
/<em> LCH mixing — preserves perceptual lightness </em>/
background: color-mix(in lch, #ff0000, #0000ff);
</p>

<p class="post-p">
/<em> Wide-gamut mixing for P3 displays </em>/
background: color-mix(in display-p3, #ff0000, #0000ff);
</code></pre>
</p>

<p class="post-p">
Here's the difference visually: mixing red and blue in sRGB gives you a dark purplish-gray. In OKLCH, you get a vibrant purple that maintains perceptual brightness through the blend.
</p>

<h2 class="post-h2">Transparent Colors and Alpha</h2>

<p class="post-p">
<code class="inline-code">color-mix()</code> handles transparency gracefully:
</p>

<pre class="code-block"><code class="language-css">/<em> Mix a color with transparent → effectively applies opacity </em>/
<p class="post-p">
background: color-mix(in srgb, #3b82f6 80%, transparent);
/<em> Same as: background: rgb(59 130 246 / 0.8) </em>/
</p>

<p class="post-p">
/<em> Mix two semi-transparent colors </em>/
background: color-mix(in srgb, rgb(255 0 0 / 0.5), rgb(0 0 255 / 0.5));
</code></pre>
</p>

<p class="post-p">
This is especially useful for creating <strong>alpha variants</strong> of design tokens:
</p>

<pre class="code-block"><code class="language-css">:root {
<p class="post-p">
--color-primary: #3b82f6;
--color-primary-80: color-mix(in srgb, var(--color-primary) 80%, transparent);
--color-primary-60: color-mix(in srgb, var(--color-primary) 60%, transparent);
--color-primary-40: color-mix(in srgb, var(--color-primary) 40%, transparent);
--color-primary-20: color-mix(in srgb, var(--color-primary) 20%, transparent);
}
</code></pre>
</p>

<h2 class="post-h2">Real-World Patterns</h2>

<h3 class="post-h3">Pattern 1: Design System Color Scales</h3>

<p class="post-p">
Instead of hand-picking 10 shades of blue, derive them from one base color:
</p>

<pre class="code-block"><code class="language-css">:root {
<p class="post-p">
--blue: #3b82f6;
</p>

<p class="post-p">
/<em> Tints (mix with white) </em>/
--blue-50:  color-mix(in oklch, var(--blue) 10%, white);
--blue-100: color-mix(in oklch, var(--blue) 25%, white);
--blue-200: color-mix(in oklch, var(--blue) 50%, white);
--blue-300: color-mix(in oklch, var(--blue) 70%, white);
</p>

<p class="post-p">
/<em> Base </em>/
--blue-500: var(--blue);
</p>

<p class="post-p">
/<em> Shades (mix with black) </em>/
--blue-700: color-mix(in oklch, var(--blue) 70%, black);
--blue-800: color-mix(in oklch, var(--blue) 50%, black);
--blue-900: color-mix(in oklch, var(--blue) 25%, black);
}
</code></pre>
</p>

<p class="post-p">
Change <code class="inline-code">--blue</code> and the entire scale updates. This is dramatically less maintenance than managing 10 separate hex values.
</p>

<h3 class="post-h3">Pattern 2: Automatic Dark Mode</h3>

<p class="post-p">
Derive dark mode colors from light mode automatically:
</p>

<pre class="code-block"><code class="language-css">:root {
<p class="post-p">
--surface: #ffffff;
--text: #0f172a;
}
</p>

<p class="post-p">
[data-theme="dark"] {
--surface: color-mix(in oklch, var(--surface), black 85%);
--text: color-mix(in oklch, var(--text), white 90%);
}
</code></pre>
</p>

<p class="post-p">
For component-level dark variants:
</p>

<pre class="code-block"><code class="language-css">.card {
<p class="post-p">
background: var(--surface);
color: var(--text);
}
</p>

<p class="post-p">
.card--elevated {
/<em> Lighten in light mode, darken in dark mode — same rule works! </em>/
background: color-mix(in oklch, var(--surface) 95%, var(--text));
}
</code></pre>
</p>

<h3 class="post-h3">Pattern 3: Accessible Contrast on Any Background</h3>

<p class="post-p">
Dynamically compute text colors that pass WCAG contrast:
</p>

<pre class="code-block"><code class="language-css">.badge {
<p class="post-p">
--badge-bg: var(--user-color, #3b82f6);
background: var(--badge-bg);
</p>

<p class="post-p">
/<em> Text is either white or black based on background luminance </em>/
color: color-mix(in oklch, var(--badge-bg) 15%, white);
}
</code></pre>
</p>

<p class="post-p">
For labels and chips where you want the text to be a darker shade of the background:
</p>

<pre class="code-block"><code class="language-css">.chip {
<p class="post-p">
background: color-mix(in oklch, var(--chip-color) 15%, transparent);
color: color-mix(in oklch, var(--chip-color) 60%, black);
border: 1px solid color-mix(in oklch, var(--chip-color) 30%, transparent);
}
</code></pre>
</p>

<h3 class="post-h3">Pattern 4: Hover and Active States</h3>

<p class="post-p">
Replace hardcoded hover colors with proportional mixing:
</p>

<pre class="code-block"><code class="language-css">.btn {
<p class="post-p">
background: var(--btn-bg, #3b82f6);
</p>

<p class="post-p">
&amp;amp;:hover {
/<em> Darken on hover — works for any color </em>/
background: color-mix(in oklch, var(--btn-bg) 85%, black);
}
</p>

<p class="post-p">
&amp;amp;:active {
background: color-mix(in oklch, var(--btn-bg) 75%, black);
}
</p>

<p class="post-p">
&amp;amp;:disabled {
background: color-mix(in oklch, var(--btn-bg) 40%, transparent);
}
}
</code></pre>
</p>

<h3 class="post-h3">Pattern 5: Gradient Stop Colors</h3>

<p class="post-p">
Calculate gradient midpoints dynamically:
</p>

<pre class="code-block"><code class="language-css">.hero-gradient {
<p class="post-p">
--from: #6366f1;
--to: #ec4899;
--mid: color-mix(in oklch, var(--from), var(--to));
</p>

<p class="post-p">
background: linear-gradient(135deg, var(--from), var(--mid), var(--to));
}
</code></pre>
</p>

<h3 class="post-h3">Pattern 6: Theming with CSS Custom Properties</h3>

<p class="post-p">
Build a complete theming system:
</p>

<pre class="code-block"><code class="language-css">:root {
<p class="post-p">
--hue: 220;
--chroma: 0.12;
--lightness: 55%;
</p>

<p class="post-p">
--color-primary: oklch(var(--lightness) var(--chroma) var(--hue));
--color-primary-hover: color-mix(in oklch, var(--color-primary) 85%, black);
--color-primary-light: color-mix(in oklch, var(--color-primary) 15%, transparent);
--color-primary-text: color-mix(in oklch, var(--color-primary) 30%, white);
}
</p>

<p class="post-p">
[data-theme="green"] {
--hue: 160;
--chroma: 0.14;
}
</p>

<p class="post-p">
[data-theme="rose"] {
--hue: 340;
--chroma: 0.16;
}
</code></pre>
</p>

<p class="post-p">
One <code class="inline-code">data-theme</code> attribute changes the entire palette.
</p>

<h2 class="post-h2">Performance Considerations</h2>

<p class="post-p">
<code class="inline-code">color-mix()</code> is computed at <strong>used-value time</strong>, meaning the browser evaluates it once per element per frame — similar to <code class="inline-code">calc()</code>. For static values, there's essentially zero runtime cost. For values that change (e.g., via <code class="inline-code">:hover</code> or custom property changes), recomputation is negligible.
</p>

<p class="post-p">
<strong>Prefer <code class="inline-code">color-mix()</code> over JavaScript color manipulation.</strong> Computing colors in JS requires reading computed styles, doing math, and writing back — triggering layout thrashing. CSS <code class="inline-code">color-mix()</code> avoids all of that.
</p>

<h2 class="post-h2">Browser Support</h2>

<p class="post-p">
As of May 2026, <code class="inline-code">color-mix()</code> is <strong>Baseline: Widely Available</strong>:
</p>

<ul class="post-ul"><li class="post-li">Chrome/Edge 111+</li>
<li class="post-li">Firefox 113+</li>
<li class="post-li">Safari 16.2+</li>
<li class="post-li">All major mobile browsers</li>
</ul>
<p class="post-p">
No polyfill needed. It's safe to ship to production.
</p>

<h2 class="post-h2">When NOT to Use color-mix()</h2>

<p class="post-p">
<strong>Predefined design tokens.</strong> If your design system already defines every shade, <code class="inline-code">color-mix()</code> adds unnecessary complexity.
</p>

<p class="post-p">
<strong>Complex multi-stop gradients.</strong> For 3+ color blends, use gradient syntax directly.
</p>

<p class="post-p">
<strong>Critical brand colors.</strong> Automatically derived colors may not match brand guidelines exactly. Always test against brand standards.
</p>

<p class="post-p">
<strong>Color space precision.</strong> sRGB mixing can produce unexpected desaturated midpoints. Always use OKLCH for perceptual consistency unless you have a specific reason to use another space.
</p>

<p class="post-p">

Open it alongside this guide to build intuition for how each color space behaves.
</p>

<h2 class="post-h2">Key Takeaways</h2>

<ul class="post-ul"><li class="post-li"><strong>Use OKLCH by default</strong> — it produces the most natural, perceptually uniform blends</li>
<li class="post-li"><strong>Derive, don't hand-pick</strong> — compute shades, tints, and states from base colors</li>
<li class="post-li"><strong>Combine with custom properties</strong> for zero-JS dynamic theming</li>
<li class="post-li"><strong>Works everywhere</strong> — Baseline since early 2024, no polyfills needed</li>
<li class="post-li"><strong>Prefer over JS color math</strong> — CSS-side computation avoids layout thrashing</li>
</ul>
<p class="post-p">
<code class="inline-code">color-mix()</code> joins CSS nesting, <code class="inline-code">:has()</code>, container queries, and cascade layers as part of the modern CSS renaissance. It eliminates an entire class of preprocessor dependencies and JavaScript color utilities. Start using it today.
</p>
