CSS Scroll-Driven Animations: Replace Intersection Observer with 3 Lines of CSS

Scroll-driven animations let you link CSS animation progress directly to scroll position — no JavaScript, no IntersectionObserver, no requestAnimationFrame. The animation-timeline property with scroll() and view() timelines runs entirely on the compositor thread for 60fps jank-free scroll effects. Complete guide with 12 production-ready presets, performance deep-dive, named timelines, animation-range mastery, and cross-browser fallback strategies.

The Scroll-Animation Problem: 15 Years of JavaScript

Every parallax effect you've ever built. Every "fade in on scroll" reveal. Every sticky header that changes size. Every progress bar tied to reading position. For 15 years, every single one required JavaScript — an IntersectionObserver or scroll event listener, a requestAnimationFrame loop, and manual interpolation between states.

The problem: JavaScript runs on the main thread. Every scroll event fires at up to 60 times per second during active scrolling. If your handler takes even 3ms to run, that's 3ms stolen from frame budget. On mid-range mobile devices, this means jank — visible stuttering where animations hitch or tear.

CSS Scroll-Driven Animations eliminate all of this. Instead of watching scroll position in JavaScript and manually updating element properties, you declare the animation once in CSS and let the browser run it natively on the compositor thread — zero main thread involvement, guaranteed 60fps, and 3-10x better battery life on mobile.

Before (JavaScript): 30+ lines of imperative code

const observer = new IntersectionObserver((entries) => {
  entries.forEach(entry => {
    const ratio = entry.intersectionRatio;
    entry.target.style.opacity = ratio;
    entry.target.style.transform = `translateY(${20 * (1 - ratio)}px)`;
  });
}, { threshold: Array.from({length: 100}, (_, i) => i / 100) });
document.querySelectorAll('.reveal').forEach(el => observer.observe(el));

After (CSS): 3 lines of declarative animation

.reveal {
  animation: fade-up linear both;
  animation-timeline: view();
  animation-range: entry 0% entry 100%;
}

How Scroll-Driven Animations Work: The Core Concepts

Scroll-driven animations extend the CSS Animations model with a new concept: instead of time driving the animation progress (the default animation-timeline: auto), scroll position drives it. The browser maps the scroll offset of an element — or an element's visibility within a scrollport — to a 0–100% progress value that feeds into your regular @keyframes.

The key property is animation-timeline, which accepts one of three values:

ValueWhat Drives ProgressProgress Range
scroll()Scroll position of a scroll container0% = top of scrollable area, 100% = bottom
view()Element's visibility within the scrollport0% = element enters scrollport, 100% = element exits
<named-timeline>Custom timeline defined by scroll-timeline propertyWhatever you define with scroll-timeline-axis

The critical difference: scroll() is about the scroll container's position. view() is about the element's visibility within that container. Use scroll() for reading-progress bars, parallax backgrounds, and shrinking headers. Use view() for entrance animations, fade-in reveals, and staggered list effects.

The scroll() Timeline: Progress Bars, Parallax, and Shrinking Headers

The scroll() function maps scroll offset to animation progress. Its full signature: 

animation-timeline: scroll(<scroller> <axis>);

/* Examples */
animation-timeline: scroll();              /* nearest ancestor scroller, block axis */
animation-timeline: scroll(nearest);       /* same as above, explicit */
animation-timeline: scroll(root);          /* document scroll position */
animation-timeline: scroll(self);          /* element's own scrollable overflow */
animation-timeline: scroll(inline);        /* horizontal scroll (x-axis) */
animation-timeline: scroll(root block);    /* document scroll, vertical axis */

Scroller reference: nearest walks up the DOM to the first scrollable ancestor. root is always the document viewport. self means the element itself must have overflow: scroll | auto.

Axis: block (logical vertical), inline (logical horizontal), x, or y.

Recipe 1: Reading Progress Bar

The classic "how far through this article" bar at the top of blog posts. Previously required a scroll event + rAF loop updating width. Now: 

.reading-progress {
  position: fixed;
  top: 0;
  left: 0;
  height: 3px;
  background: linear-gradient(90deg, #6366f1, #a855f7);

  animation: grow-width linear;
  animation-timeline: scroll(root);
  transform-origin: 0 0;
}

@keyframes grow-width {
  from { transform: scaleX(0); }
  to   { transform: scaleX(1); }
}

That's it. Zero JavaScript. The progress bar tracks document scroll from 0% to 100% and runs entirely on the compositor.

Recipe 2: Parallax Background

The hero-section parallax effect — a background image that moves slower than foreground content as you scroll. Every website has one, and every one currently uses JavaScript. 

.hero {
  background-image: url('mountains.webp');
  background-size: cover;
  background-position: center;

  animation: parallax-bg linear;
  animation-timeline: scroll(root);
}

@keyframes parallax-bg {
  from { background-position-y: 0%; }
  to   { background-position-y: 100%; }
}

Want a slower parallax rate? Use animation-range to compress the animation over a shorter scroll distance — the background moves less per page-scroll-unit. 

.hero {
  animation: parallax-bg linear;
  animation-timeline: scroll(root);
  animation-range: 0% 50%;  /* animation completes in first 50% of scroll */
}

Recipe 3: Shrinking Sticky Header

.site-header {
  position: sticky;
  top: 0;
  padding: 1.5rem;

  animation: shrink-header linear;
  animation-timeline: scroll(root);
  animation-range: 0% 200px;
}

@keyframes shrink-header {
  from {
    padding: 1.5rem;
    background: rgba(15, 23, 42, 0);
    backdrop-filter: blur(0px);
  }
  to {
    padding: 0.5rem;
    background: rgba(15, 23, 42, 0.9);
    backdrop-filter: blur(12px);
  }
}

The header transitions from transparent-lg to opaque-sm over the first 200px of scroll. The animation-range: 0% 200px syntax means "start at 0px scroll, finish at 200px scroll." After 200px the animation is done and the header stays in its final state.

The view() Timeline: Entrance Animations, Staggered Lists, and Scroll-Triggered Reveals

The view() function tracks an element's visibility as it crosses the scrollport. This is the IntersectionObserver killer. 

animation-timeline: view(<axis> <view-timeline-inset>);

/* Examples */
animation-timeline: view();                        /* default: block axis, no inset */
animation-timeline: view(block);                   /* vertical scroll */
animation-timeline: view(inline);                  /* horizontal scroll */
animation-timeline: view(block 20%);               /* 20% inset from all sides */
animation-timeline: view(block 10% 20%);           /* 10% start, 20% end inset */
animation-timeline: view(y 20%);                   /* explicit y axis + inset */

View-timeline-inset: Shrinks (positive values) or expands (negative values) the scrollport for determining visibility. Inset 20% means the element must be 20% inside the viewport to be considered "visible." Negative insets like -10% mean the animation starts before the element enters the viewport.

The key realization: a view() timeline has four distinct phases:

  • cover 0% — element starts entering scrollport (first pixel visible)
  • contain 0% — element is fully inside scrollport
  • contain 100% — element starts leaving scrollport
  • cover 100% — element fully exits scrollport

You control which phase drives the animation with animation-range (detailed below), but the common pattern is entry (element enters) for reveal animations and exit for hiding animations.

Recipe 4: Fade-Up Reveal on Scroll

.reveal {
  opacity: 0;
  transform: translateY(30px);

  animation: fade-up 0.5s ease-out forwards;
  animation-timeline: view();
  animation-range: entry 10% entry 100%;
}

@keyframes fade-up {
  from {
    opacity: 0;
    transform: translateY(30px);
  }
  to {
    opacity: 1;
    transform: translateY(0);
  }
}

The animation-range: entry 10% entry 100% means: start when the element is 10% into the viewport, finish when the element is fully visible (entry 100% = first pixel at top of viewport). The animation runs only during the entry phase, not the entire crossing.

Recipe 5: Staggered List with Custom Property

.staggered-list li {
  opacity: 0;
  transform: translateX(-20px);

  animation: slide-in 0.4s ease-out forwards;
  animation-timeline: view();
  animation-range: entry 0% entry 100%;

  /* No JavaScript needed for staggering! */
  animation-delay: calc(var(--item-index) * 0.1s);
}

/* In HTML: <li style="--item-index: 0">...</li> */

While you still need an inline style for the index, the animation itself is pure CSS. No JavaScript animation libraries, no gsap.registerPlugin(ScrollTrigger), no 50KB of overhead.

Recipe 6: Horizontal Scroll Gallery

.gallery-track {
  display: flex;

  animation: horizontal-scroll linear;
  animation-timeline: view(inline);
  animation-range: cover 0% cover 100%;
}

@keyframes horizontal-scroll {
  from { translate: 0 0; }
  to   { translate: calc(var(--track-width) * -1 + 100vw) 0; }
}

Named Timelines: The scroll-timeline Property

For complex layouts with multiple elements animating against the same scroll source, named timelines prevent repetition and improve maintainability. Define a timeline once, reference it everywhere. 

/* Define the timeline on the scroll container */
.scroll-container {
  overflow-y: auto;
  scroll-timeline: --gallery-timeline block;
}

/* Reference it on any descendant */
.gallery-progress {
  animation: progress-bar linear;
  animation-timeline: --gallery-timeline;
}

.gallery-items img {
  animation: reveal linear;
  animation-timeline: --gallery-timeline;
  animation-range: entry 0% entry 100%;
}

The scroll-timeline shorthand accepts <name> <axis>. Any element inside the scroll container can reference --gallery-timeline — no DOM traversal, no JavaScript plumbing, just CSS.

animation-range: Precision Over What Part of Scroll Drives the Animation

Without animation-range, a scroll() timeline maps the entire scroll range (0–100% of the scroll container) to 0–100% of your keyframes. With animation-range, you can compress or expand this mapping.

animation-range accepts two values: the start offset and end offset of the animation within the timeline. Each offset can be:

  • A length (e.g., 200px): absolute scroll distance
  • A percentage (e.g., 50%): relative to the full timeline range
  • A named range for view() timelines: cover, contain, entry, exit, entry-crossing, exit-crossing
Named RangeStart Offset MeaningEnd Offset Meaning
coverElement starts entering scrollportElement fully exits scrollport
containElement fully inside scrollportElement starts leaving scrollport
entryElement starts entering scrollportElement fully inside scrollport
exitElement starts leaving scrollportElement fully exits scrollport
entry-crossingElement starts enteringElement crosses completely past entry
exit-crossingElement starts leavingElement crosses completely past exit

Each named range also accepts a percentage modifier: entry 50% means "halfway through the entry phase." This gives surgical precision: 

/* Element starts fading when 20% visible, fully opaque at 80% visible */
animation-range: entry 20% entry 80%;

/* Element only animates during the center of the viewport crossing */
animation-range: contain 0% contain 100%;

Performance: The Compositor-Only Advantage

This is where CSS Scroll-Driven Animations become genuinely transformative. The entire pipeline runs on the compositor thread.

AspectJavaScript (IntersectionObserver)CSS Scroll-Driven Animations
ThreadMain thread (blocked by JS execution)Compositor thread (never blocked)
Frame budget impact~1-3ms per element per frame0ms (free)
Jank during heavy JSYes — scroll effects freezeNo — compositor always runs
BatteryCPU-pinned during scrollGPU-efficient, minimal CPU
Throttled in background tabsYes (rAF paused)No (compositor unaffected)
Animatable propertiesAny (via JS mutation)GPU-friendly only (transform, opacity, filter)

The compositor-thread guarantee means your scroll animations keep running at 60fps even when the main thread is slammed with JavaScript — loading analytics, processing data, rendering React components. This is physically impossible to achieve with JavaScript scroll watchers.

But wait — CSS animations can only animate compositable properties. If you need to animate background-color, font-size, or non-composited properties on scroll, you must use JavaScript. However, for the 90% of scroll effects that are transforms and opacity (reveals, parallax, scaling, rotation, fading), CSS scroll-driven animations are categorically superior.

The Complete 12-Recipe Production Cheatsheet

Recipe 7: Image Scale-Reveal Hero

.hero-image {
  animation: scale-reveal linear;
  animation-timeline: view();
  animation-range: entry 0% entry 100%;
}
@keyframes scale-reveal {
  from { transform: scale(1.2); opacity: 0; filter: blur(10px); }
  to   { transform: scale(1); opacity: 1; filter: blur(0); }
}

Recipe 8: Counter That Counts Up on Scroll

.counter {
  animation: count-up both steps(1);
  animation-timeline: view();
  animation-range: entry 0% entry 100%;
  counter-reset: num var(--target);
}
.counter::after {
  content: counter(num);
}
@keyframes count-up {
  from { counter-increment: num calc(var(--target) * -1); }
  to   { counter-increment: num 0; }
}

Recipe 9: Sticky Cards That Stack

.card-stack .card {
  position: sticky;
  top: 80px;
  animation: card-scale linear;
  animation-timeline: view();
  animation-range: cover 0% cover 100%;
}
@keyframes card-scale {
  from { transform: scale(0.92); opacity: 0.6; }
  30%  { transform: scale(1); opacity: 1; }
  70%  { transform: scale(1); opacity: 1; }
  to   { transform: scale(0.92); opacity: 0.6; }
}

Recipe 10: Clip-Path Reveal

.clip-reveal {
  animation: clip-unveil linear;
  animation-timeline: view();
  animation-range: entry 20% entry 100%;
}
@keyframes clip-unveil {
  from { clip-path: inset(100% 0% 0% 0%); }
  to   { clip-path: inset(0% 0% 0% 0%); }
}

Recipe 11: Rotating Text Carousel on Scroll

.rotating-words {
  animation: rotate-words linear;
  animation-timeline: scroll(root);
  animation-range: 0% 100%;
}
@keyframes rotate-words {
  0%   { translate: 0 -100%; }
  100% { translate: 0 100%; }

Recipe 12: SVG Path Drawing on Scroll

.draw-path {
  animation: draw linear both;
  animation-timeline: view();
  animation-range: entry 0% entry 100%;
}
@keyframes draw {
  from { stroke-dashoffset: var(--path-length); }

}

Browser Support and Progressive Enhancement

As of June 2026, animation-timeline: scroll() and animation-timeline: view() are Baseline 2024 — shipping in Chrome 115+, Edge 115+, Safari 18+, and Firefox 128+. Global coverage is approximately 89% of users.

For the remaining 11%, use @supports to provide a fallback: 

.reveal {
  /* Default: always visible (no animation) */
  opacity: 1;
}

@supports (animation-timeline: view()) {
  .reveal {
    opacity: 0;
    animation: fade-up 0.5s ease-out forwards;
    animation-timeline: view();
    animation-range: entry 0% entry 100%;
  }
}

Detect at runtime: Use CSS.supports('animation-timeline', 'view()') to conditionally load polyfills or fall back to IntersectionObserver for unsupported browsers. The scroll-timeline polyfill (by Bramus/flackr) covers older Chromium versions back to Chrome 69.

Common Pitfalls

  • Scrollable ancestor not found: scroll(nearest) walks up the DOM. If no ancestor is scrollable (overflow: scroll/auto + content overflow), it falls back to the root scroller. Verify your container has actual overflow.
  • animation-fill-mode matters: Always use both or forwards for view timelines — otherwise the element snaps back when fully visible.
  • animation-range works with scroll() too: It's not just for view(). Compress a scroll() timeline over a specific scroll distance for variable-rate effects.
  • Not every property composites: Animating width, height, font-size, or background-color on scroll still triggers layout/paint. Stick to transform and opacity for compositor-only performance.
  • Firefox vs. Chrome behavior divergence: As of Firefox 128, named timelines using scroll-timeline have subtle differences in animation-range handling. Test cross-browser.
  • Custom properties don't animate: You can't animate --my-var from 0 to 100 on scroll. Use @property registration for typed custom properties that can animate.

Key Takeaways

  • CSS Scroll-Driven Animations are the biggest animation feature since CSS Animations itself. They eliminate the JavaScript-middleman for the most common scroll effects.
  • scroll() for container position, view() for element visibility. The two timelines cover completely different use cases — learn both.
  • animation-range is the secret weapon. Without it, you're stuck with full-timeline mappings. With it, you have surgical control over what scroll interval drives each animation.
  • Named timelines scale. Define once on the container, reference on every child. Clean, maintainable, zero repetition.
  • Compositor-only performance is the killer feature. 0ms main thread cost per frame. Jank-resistant even under heavy JS load. This is physically impossible with JavaScript.
  • Progressive enhancement is trivial. One @supports block and you have full fallback. No complex polyfill loading required for most use cases.
  • Shipping now. 89% global coverage in 2026. By 2027, this will be as fundamental as CSS Grid — you'll wonder how you ever built scroll effects without it.
