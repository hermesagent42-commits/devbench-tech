CSS interpolate-size and calc-size(): Finally, Animate to height:auto in 2026

For decades, animating to height:auto has been the holy grail of CSS animations — every solution required JavaScript. Now with interpolate-size: allow-keywords and calc-size(), browsers natively animate between fixed lengths and intrinsic sizes. Complete guide with production patterns, browser support, and the death of JS height hacks.

June 9, 202610 min readby DevBench
CSSinterpolate-sizecalc-size()AnimationIntrinsic SizingBaseline 2026Transitions

For 25 years, one CSS animation has been impossible: smoothly expanding a collapsed element to its natural height: auto. Every solution — JavaScript scrollHeight measurement, ResizeObserver hacks, max-height workarounds — came with compromises. In 2026, the browser finally ships a native solution: interpolate-size: allow-keywords and the calc-size() function.

These two features work together to unlock animations between fixed lengths and intrinsic sizes — auto, min-content, max-content, and fit-content. They're shipping as Baseline 2026 across Chrome, Firefox, and Safari. This is the most significant CSS animation advancement since keyframes.

The Problem: Why height:auto Has Resisted Animation

CSS transitions and animations need calculable interpolated values. When you go from 0px to 200px, the browser can compute every intermediate frame — at 50% progress, the height is 100px.

But auto is not a number. It's a directive meaning "figure out the size from the content." The browser can't interpolate from 0px to "whatever the content needs" because it doesn't know the target until layout runs — and layout doesn't run at animation-frame granularity.

The core problem: CSS interpolation requires both the start and end values to be of the same calculable type. auto is a keyword, not a length — so transition: height 0.3s simply snaps between states with no animation.

Developers have worked around this for decades. Every approach had a trade-off:

  • max-height hack: Set max-height: 500px and transition that. Problem: if content is smaller than 500px, the animation is jarringly fast. If content is larger, it gets clipped. Hardcoding a max height is fragile.
  • JavaScript scrollHeight: Measure with element.scrollHeight, set height to a pixel value, then animate. Problem: requires DOM access, breaks with dynamic content, and causes layout thrashing.
  • FLIP technique: Record the auto height, set it to a fixed value, animate, then remove the inline style. Problem: complex and prone to race conditions with dynamic content.
  • ResizeObserver + requestAnimationFrame: Continuously poll the computed height and feed it to a JS-driven animation. Problem: runs on the main thread, consumes CPU, and still isn't truly smooth.

The Solution: interpolate-size and calc-size()

Two complementary features ship together in 2026:

interpolate-size: allow-keywords

This is a new CSS property that tells the browser: "when transitioning or animating this element, I want you to handle intrinsic sizing keywords as interpolation endpoints."

/* The global opt-in */
:root {
  interpolate-size: allow-keywords;
}

/* Or per-element */
.collapsible {
  interpolate-size: allow-keywords;
  overflow: hidden;
  height: 0;
  transition: height 0.3s ease;
}

.collapsible.open {
  height: auto; /* ← This now animates! */
}

With just interpolate-size: allow-keywords on the element (or globally on :root), transitions to and from height: auto, width: auto, min-content, and max-content just work. No JavaScript. No hacks. No max-height guessing.

What makes this special: The browser now calculates the intrinsic size as a pixel value at transition start, then interpolates smoothly. It's essentially doing the scrollHeight measurement for you, at native speed, off the main thread where possible.

calc-size(): Math with Intrinsic Sizes

calc-size() is a companion function that lets you perform calculations on intrinsic sizes. While calc() only works with resolvable lengths, calc-size() accepts keywords like auto, min-content, max-content, and fit-content as operands:

/* Animate to auto + 16px padding */
.drawer {
  interpolate-size: allow-keywords;
  height: 0;
  overflow: hidden;
  transition: height 0.3s ease;
}

.drawer.open {
  height: calc-size(auto, size + 16px);
  /* ^ Resolves auto to a pixel value, adds 16px */
}

/* Animate to 80% of the max-content width */
.expandable-column {
  interpolate-size: allow-keywords;
  width: 0;
  transition: width 0.4s ease;
}

.expandable-column.open {
  width: calc-size(max-content, size * 0.8);
}

The calc-size() function accepts two arguments: a basis keyword (what to measure), and a calculation expression where size represents the resolved pixel value of that basis. This unlocks patterns like "animate to auto plus padding" or "expand to 80% of the max-content width" — all in pure CSS.

Production Patterns

Pattern 1: Accordion / FAQ Section

.accordion-panel {
  interpolate-size: allow-keywords;
  height: 0;
  overflow: hidden;
  transition: height 0.35s cubic-bezier(0.4, 0, 0.2, 1);
}

.accordion-panel[open] {
  height: auto;
}

That's it. No JavaScript required for the animation. The <details> element with [open] attribute or a simple class toggle is all you need. The browser measures the content height once and interpolates perfectly.

Pattern 2: Notification Toast Slide-Down

.toast {
  interpolate-size: allow-keywords;
  height: 0;
  opacity: 0;
  margin-bottom: 0;
  overflow: hidden;
  transition:
    height 0.3s ease,
    opacity 0.3s ease,
    margin-bottom 0.3s ease;
}

.toast.visible {
  height: auto;
  opacity: 1;
  margin-bottom: 12px;
}

Multi-property transitions work seamlessly. The toast slides into existence with its natural height, then slides out when dismissed. This is what every notification library has been faking with JavaScript for years.

Pattern 3: Progressive Disclosure with calc-size()

.details-panel {
  interpolate-size: allow-keywords;
  height: 0;
  overflow: hidden;
  transition: height 0.4s cubic-bezier(0.25, 0.8, 0.25, 1.2);
}

.details-panel.expanded {
  height: calc-size(auto, size + 24px);
  /* Natural height plus breathing room — no layout shift */
}

The + 24px gives the panel a comfortable bottom margin that's part of the animated space — no separate margin animation needed. This is cleaner and more predictable than animating margin separately.

Pattern 4: Width Animation for Sidebar

.sidebar {
  interpolate-size: allow-keywords;
  width: 48px;
  overflow: hidden;
  white-space: nowrap;
  transition: width 0.3s ease;
}

.sidebar.expanded {
  width: calc-size(max-content, size + 16px);
}

Instead of hardcoding a sidebar width (which breaks when labels change or translations are longer), max-content adapts to the actual content. The calc-size() function adds 16px of padding to the calculated width.

Understanding the Two-Part Opt-In

You must use both interpolate-size and an intrinsic keyword together for the animation to work:

SetupBehavior
interpolate-size: allow-keywords + height: auto✅ Smooth interpolation from any fixed length to the content's natural height
interpolate-size: allow-keywords + calc-size(auto, …)✅ Smooth interpolation with calculations applied to the resolved size
No interpolate-size, just height: auto❌ Snaps — no animation (legacy behavior)
interpolate-size: allow-keywords + fixed height: 200px✅ Animate — but only between fixed lengths (same as before)

The property is an explicit opt-in because changing the animation behavior of auto is a web-compatible risk. Some sites may have relied on auto values not interpolating. The opt-in protects backward compatibility while enabling the feature for developers who want it.

Pro tip: Set interpolate-size: allow-keywords on :root in your global stylesheet. This makes the behavior available site-wide without needing to add it to every animated element. The performance overhead is negligible — intrinsic size measurement only happens during active transitions.

Supported Keywords

Both interpolate-size: allow-keywords and calc-size() support five intrinsic sizing keywords:

  • auto — the browser's default sizing (content-based for height, fill-available for width in most contexts)
  • min-content — the smallest size the content can occupy without overflowing (the longest word)
  • max-content — the size the content would take if allowed infinite space (all on one line)
  • fit-content — min(max-content, max(min-content, available-size)) — clamps to the available container
  • stretch — fill the available space in the containing block

These keywords can be used as endpoints in any CSS property that accepts length values and supports transitions — height, width, min-height, max-width, flex-basis, grid-template-rows, and more.

Performance and Best Practices

  • Add overflow: hidden to collapsed elements. Without it, content overflows during the transition because the element's height hasn't caught up to the content yet.
  • Prefer transform and opacity when possible. These animate on the compositor thread and avoid layout recalculations. height and width transitions trigger layout, which is more expensive. Use interpolate-size for elements whose size genuinely changes, not for decorative animations.
  • Use will-change: height sparingly. It can help with jank on complex pages, but overusing it consumes GPU memory.
  • Test with varying content lengths. A short notification and a long one should both animate gracefully. That's the whole point of using auto instead of a fixed pixel value.

Browser Support and Progressive Enhancement

Baseline 2026: Chrome 134+, Firefox 137+, Safari 18.4+. All three major engines ship interpolate-size and calc-size() in 2026.

For older browsers, the behavior degrades gracefully — they simply snap between states without animation, exactly as they always have. You can use feature detection to apply JavaScript fallbacks only when needed:

/* Feature query for progressive enhancement */
@supports (interpolate-size: allow-keywords) {
  .accordion-panel {
    interpolate-size: allow-keywords;
    height: 0;
    transition: height 0.3s ease;
  }
  .accordion-panel.open {
    height: auto;
  }
}

/* Fallback: JavaScript-driven animation for older browsers */
@supports not (interpolate-size: allow-keywords) {
  .accordion-panel {
    height: auto; /* No animation */
    max-height: none;
  }
}

In practice, for most sites shipping in 2026 and beyond, you can safely use this without fallbacks. The vast majority of traffic will come from browsers that support it, and the snap fallback is perfectly acceptable.

The Bigger Picture: Intrinsic Web Layout

interpolate-size and calc-size() are part of a broader trend in modern CSS: embracing intrinsic sizing. For years, CSS layout relied on developers specifying explicit pixel values — width: 300px, height: 200px. But the web is inherently fluid, and content is unpredictable.

Features like Container Queries, min()/max()/clamp(), auto-sized Grid tracks, and now interpolated intrinsic sizes all point in the same direction: the browser should figure out sizing, and developers should describe constraints.

These two new features close one of the last major gaps in CSS animations — and they do it without adding complexity. Two declarations, and a problem that's persisted since CSS2 becomes trivial.
