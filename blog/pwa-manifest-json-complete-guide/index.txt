<p class="post-p">
The <code class="inline-code">manifest.json</code> file is the single source of truth for how your web app appears when installed on a user's device. It controls the app name, icon, theme color, display mode, and dozens of other details that transform a website into a native-like experience.
</p>

<p class="post-p">
Without it, there's no "Add to Home Screen" prompt, no splash screen, and no standalone window — just a browser tab.
</p>

<h2 class="post-h2">The Minimum Viable Manifest</h2>

<p class="post-p">
A valid manifest needs only a few fields:
</p>

<pre class="code-block"><code class="language-json">{
<p class="post-p">
"name": "My App",
"short_name": "App",
"start_url": "/",
"display": "standalone",
"icons": [
{
"src": "/icon-192.png",
"sizes": "192x192",
"type": "image/png"
},
{
"src": "/icon-512.png",
"sizes": "512x512",
"type": "image/png"
}
]
}
</code></pre>
</p>

<p class="post-p">
Link it from every page with a single <code class="inline-code">&lt;link&gt;</code> tag in your <code class="inline-code">&lt;head&gt;</code>:
</p>

<pre class="code-block"><code class="language-html">&amp;lt;link rel="manifest" href="/manifest.json" /&amp;gt;
<p class="post-p">
</code></pre>
</p>

<h2 class="post-h2">Required vs. Recommended Fields</h2>

<h3 class="post-h3">Required by Chrome for Install Prompt</h3>

<p class="post-p">
Chrome's installability criteria (the "beforeinstallprompt" event requires):
</p>

<ul class="post-ul"><li class="post-li">A valid <code class="inline-code">manifest.json</code> linked from the page</li>
<li class="post-li">At least a <strong>192x192</strong> and <strong>512x512</strong> icon</li>
<li class="post-li"><code class="inline-code">display</code> set to <code class="inline-code">standalone</code>, <code class="inline-code">fullscreen</code>, or <code class="inline-code">minimal-ui</code> (but not <code class="inline-code">browser</code>)</li>
<li class="post-li">The site served over HTTPS</li>
<li class="post-li">A registered service worker with a <code class="inline-code">fetch</code> event handler</li>
</ul>
<h3 class="post-h3">Recommended for Quality</h3>

<p class="post-p">
Beyond the minimum, these fields significantly improve the user experience:
</p>

<pre class="code-block"><code class="language-json">{
<p class="post-p">
"description": "A brief description of what your app does",
"theme_color": "#1a1a2e",
"background_color": "#0f0f1a",
"orientation": "portrait-primary",
"scope": "/app/",
"lang": "en",
"categories": ["productivity", "utilities"],
"screenshots": [
{
"src": "/screenshot-1.png",
"sizes": "1280x720",
"type": "image/png",
"label": "Home screen with dashboard"
}
]
}
</code></pre>
</p>

<h2 class="post-h2">Display Modes Explained</h2>

<p class="post-p">
The <code class="inline-code">display</code> field controls the browser chrome around your app:
</p>

<p class="post-p">
| Mode | Browser Chrome | Status Bar | Best For |
|------|---------------|------------|----------|
| <code class="inline-code">standalone</code> | None (own window) | Yes | Most apps — looks native |
| <code class="inline-code">fullscreen</code> | None at all | No | Games, immersive experiences |
| <code class="inline-code">minimal-ui</code> | Back/forward/reload | Yes | Content-focused apps |
| <code class="inline-code">browser</code> | Full browser chrome | Yes | Standard web page |
</p>

<p class="post-p">
<strong>Recommendation:</strong> Use <code class="inline-code">standalone</code> for most apps. It gives you a native-looking window with a status bar but no URL bar or browser buttons.
</p>

<h2 class="post-h2">Icons: The Complete Story</h2>

<p class="post-p">
Icons are the make-or-break for a good PWA. Here's the recommended set:
</p>

<pre class="code-block"><code class="language-json">"icons": [
<p class="post-p">
{ "src": "/icon-48.png",  "sizes": "48x48",   "type": "image/png" },
{ "src": "/icon-72.png",  "sizes": "72x72",   "type": "image/png" },
{ "src": "/icon-96.png",  "sizes": "96x96",   "type": "image/png" },
{ "src": "/icon-144.png", "sizes": "144x144", "type": "image/png" },
{ "src": "/icon-192.png", "sizes": "192x192", "type": "image/png" },
{ "src": "/icon-256.png", "sizes": "256x256", "type": "image/png" },
{ "src": "/icon-384.png", "sizes": "384x384", "type": "image/png" },
{ "src": "/icon-512.png", "sizes": "512x512", "type": "image/png" }
]
</code></pre>
</p>

<p class="post-p">
<strong>Why so many sizes?</strong> Different platforms use different sizes:
</p>

<ul class="post-ul"><li class="post-li"><strong>Android</strong> — Uses 192x192 for the home screen, 512x512 for the splash screen</li>
<li class="post-li"><strong>iOS (Safari)</strong> — Uses the <code class="inline-code">apple-touch-icon</code> link tag (not manifest icons), typically 180x180</li>
<li class="post-li"><strong>Windows</strong> — Uses 256x256 or larger for tiles</li>
<li class="post-li"><strong>ChromeOS</strong> — Uses 512x512</li>
</ul>
<p class="post-p">
<strong>Pro tip:</strong> Provide a maskable icon with a safe zone (padding) so Android can adapt it to any shape:
</p>

<pre class="code-block"><code class="language-json">{
<p class="post-p">
"src": "/icon-maskable.png",
"sizes": "512x512",
"type": "image/png",
"purpose": "maskable"
}
</code></pre>
</p>

<p class="post-p">
Maskable icons should have at least 40% padding (safe zone of 60% inner area). Use a tool like <a href="https://maskable.app" class="post-link" target="_blank" rel="noopener noreferrer">Maskable.app</a> to test your icon.
</p>

<h2 class="post-h2">Theme &amp; Background Colors</h2>

<p class="post-p">
These two colors control the startup experience:
</p>

<ul class="post-ul"><li class="post-li"><strong><code class="inline-code">theme_color</code></strong> — The color of the status bar / toolbar in the standalone window</li>
<li class="post-li"><strong><code class="inline-code">background_color</code></strong> — The color shown while the app loads (before any CSS)</li>
</ul>
<pre class="code-block"><code class="language-json">{
<p class="post-p">
"theme_color": "#1a1a2e",
"background_color": "#0f0f1a"
}
</code></pre>
</p>

<p class="post-p">
<strong>Best practice:</strong> Set <code class="inline-code">background_color</code> to the same value as your page's <code class="inline-code">&lt;body&gt;</code> background. This prevents a flash of white during app load. Set <code class="inline-code">theme_color</code> to your primary brand color for a cohesive native feel.
</p>

<h2 class="post-h2">Screenshots: The Store Listing</h2>

<p class="post-p">
Screenshots appear in the app install dialog on Android and in app stores if you submit your PWA. Chrome requires at least one screenshot for the "richer install UI":
</p>

<pre class="code-block"><code class="language-json">"screenshots": [
<p class="post-p">
{
"src": "/screenshot-wide.png",
"sizes": "1280x720",
"type": "image/png",
"label": "Dashboard view with analytics"
},
{
"src": "/screenshot-mobile.png",
"sizes": "750x1334",
"type": "image/png",
"label": "Mobile view with navigation"
}
]
</code></pre>
</p>

<p class="post-p">
<strong>Requirements:</strong> Screenshots must be at least 320x320 and at most 3840x3840. Chrome recommends landscape (wider than tall) screenshots for the best presentation.
</p>

<h2 class="post-h2">App Shortcuts</h2>

<p class="post-p">
Shortcuts appear when the user long-presses or right-clicks your app icon. They provide quick access to common tasks:
</p>

<pre class="code-block"><code class="language-json">"shortcuts": [
<p class="post-p">
{
"name": "New Document",
"short_name": "New",
"description": "Create a blank document",
"url": "/new"
},
{
"name": "View Recent",
"short_name": "Recent",
"description": "Browse recently edited files",
"url": "/recent"
}
]
</code></pre>
</p>

<p class="post-p">
<strong>Limits:</strong> Chrome supports up to 10 shortcuts. Each must have at minimum a <code class="inline-code">name</code> and <code class="inline-code">url</code>.
</p>

<h2 class="post-h2">Categories</h2>

<p class="post-p">
The <code class="inline-code">categories</code> field helps app stores and the OS understand what your app does:
</p>

<pre class="code-block"><code class="language-json">"categories": ["productivity", "utilities", "education"]
<p class="post-p">
</code></pre>
</p>

<p class="post-p">
Choose from the <a href="https://www.w3.org/TR/webappmanifest/#categories-member" class="post-link" target="_blank" rel="noopener noreferrer">W3C's list of known categories</a>: books, business, education, entertainment, finance, fitness, food, games, health, kids, lifestyle, music, navigation, news, photo, productivity, shopping, social, sports, travel, utilities, weather.
</p>

<h2 class="post-h2">Testing Your Manifest</h2>

<ul class="post-ul"><li class="post-li"><strong>Chrome DevTools</strong> → Application tab → Manifest panel. Shows all parsed fields and any errors.</li>
<li class="post-li"><strong>Lighthouse</strong> — Run an audit; it validates your manifest, icons, and installability.</li>
<li class="post-li"><strong>Web App Manifest Validator</strong> — Command line: <code class="inline-code">npx web-app-manifest-validator manifest.json</code></li>
<li class="post-li"><strong>DevBench PWA Manifest Generator</strong> — <a href="/tools/pwa-manifest-generator" class="post-link" target="_blank" rel="noopener noreferrer">Build and preview manifest.json visually</a></li>
</ul>
<h2 class="post-h2">Common Mistakes</h2>

<h3 class="post-h3">1. Missing 192x192 or 512x512 icon</h3>

<p class="post-p">
Chrome requires both. Without them, the install prompt won't fire. Check that your <code class="inline-code">sizes</code> field exactly matches the actual image dimensions.
</p>

<h3 class="post-h3">2. <code class="inline-code">display: "browser"</code> (or missing <code class="inline-code">display</code>)</h3>

<p class="post-p">
This prevents the app from opening in standalone mode. Use <code class="inline-code">standalone</code>, <code class="inline-code">fullscreen</code>, or <code class="inline-code">minimal-ui</code>.
</p>

<h3 class="post-h3">3. Start URL outside of scope</h3>

<p class="post-p">
The <code class="inline-code">start_url</code> must be within the <code class="inline-code">scope</code>. If <code class="inline-code">scope</code> is <code class="inline-code">/app/</code>, the <code class="inline-code">start_url</code> cannot be <code class="inline-code">/</code>.
</p>

<h3 class="post-h3">4. No service worker</h3>

<p class="post-p">
A service worker with at minimum a <code class="inline-code">fetch</code> event listener is required for Chrome's install prompt. Even an empty one works:
</p>

<pre class="code-block"><code class="language-js">self.addEventListener('fetch', () =&amp;gt; {});
<p class="post-p">
</code></pre>
</p>

<h3 class="post-h3">5. Non-HTTPS</h3>

<p class="post-p">
PWAs require HTTPS. The only exception is <code class="inline-code">localhost</code> for development.
</p>

<h2 class="post-h2">Going Beyond</h2>

<p class="post-p">
Once your manifest is solid, the next steps for a complete PWA are:
</p>

<ul class="post-ul"><li class="post-li"><strong>Service Worker</strong> — Cache your app shell for offline access</li>
<li class="post-li"><strong>Web App Install Banner</strong> — Customize the install experience</li>
<li class="post-li"><strong>Push Notifications</strong> — Engage users with timely updates</li>
<li class="post-li"><strong>Background Sync</strong> — Handle offline writes that sync when online</li>
<li class="post-li"><strong>File Handling</strong> — Register as a file handler for your app's document types</li>
</ul>
<p class="post-p">
The manifest.json is just the beginning — but it's the foundation everything else builds on. Get it right, and your PWA will install on Android, ChromeOS, and desktop Chrome with a polished, native-like experience.
</p>
